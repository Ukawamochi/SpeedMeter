# 書き起こしベースラインで使う音声認識モデルの選定（docs/PLAN.md 第3段階 3-3）

## 決めたこと

| 項目 | 値 |
| --- | --- |
| モデル | `Systran/faster-whisper-small`（OpenAI Whisper small を CTranslate2 形式へ変換したもの） |
| 規模 | パラメータ約2.44億。Whisper の**小型版**にあたる（tiny 0.39億、base 0.74億、small 2.44億、medium 7.69億、large 15.5億） |
| 実行方法 | `faster-whisper` 1.2（CTranslate2 4.8 の推論エンジン） |
| 量子化 | **しない**（`compute_type: float32`）。理由は「量子化しない理由」を参照 |
| デバイス | `cpu`。理由は「デバイスを cpu にした理由」を参照 |
| 復号 | 貪欲（`beam_size: 1`）、言語は日本語に固定（`language: ja`）、時刻トークンなし（`without_timestamps: true`）、直前文脈なし（`condition_on_previous_text: false`）、VAD なし（`vad_filter: false`） |
| モーラの数え方 | 書き起こしに `spkrate.labels.mora.count_mora` を適用（学習ラベルと同じ経路：NFKC正規化 → pyopenjtalk で読み変換 → モーラ計数） |
| 実装 | `src/spkrate/baselines/asr.py` |
| 設定 | `configs/baselines/asr.yaml` |
| 実行 | `scripts/run_asr_baseline.py` |

## 選定の制約と、それをどう満たしたか

| 制約 | 満たし方 |
| --- | --- |
| 日本語に対応する | Whisper は多言語モデルで日本語を含む。`language: ja` を明示して言語判定を省いている |
| ローカルで動く | モデル重みを一度取得すれば、以後はネットワークなしで動く。推論は外部APIを使わない |
| 追加依存が軽い | `faster-whisper` は CTranslate2 実装で、`transformers` や別の深層学習フレームワークを持ち込まない。追加されたのは ctranslate2・tokenizers・av・huggingface-hub など |

モデル重みの取得は Hugging Face Hub から行った。CLAUDE.md の「データセットはユーザーが手動で取得・配置する」
はデータセットに対する規則であり、モデル重みは対象外である（本タスクの指示による）。取得は成功した。

## 候補の比較

検証セット（dev）から固定シード `12345` で抽出した**100件**で比較した。
テストセット（`configs/splits/test.json`）は使っていない。
実行は `scripts/run_asr_baseline.py compare --size 100 --seed 12345`、
生の結果は `/tmp/asr_model_comparison.json`。

| モデル | 精度 | ビーム幅 | 1クリップあたり | 平均絶対誤差 | 相関係数 | 最大誤差 |
| --- | --- | --- | --- | --- | --- | --- |
| tiny | float32 | 1 | 228.9ミリ秒 | 0.4391 | 0.9363 | 4.123 |
| tiny | int8 | 1 | 275.2ミリ秒 | 0.4089 | 0.9319 | 5.208 |
| base | float32 | 1 | 279.0ミリ秒 | 0.2974 | 0.9375 | 6.076 |
| base | int8 | 1 | 379.9ミリ秒 | 0.3227 | 0.9412 | 5.642 |
| base | int8 | 5 | 487.2ミリ秒 | 0.3065 | 0.9360 | 6.076 |
| **small** | **float32** | **1** | **758.7ミリ秒** | **0.1727** | **0.9671** | **4.340** ←採用 |
| small | float32 | 5 | 1052.8ミリ秒 | 0.2166 | 0.9386 | 4.340 |
| small | int8 | 1 | 1290.9ミリ秒 | 0.2304 | 0.9434 | 4.340 |
| small | int8 | 5 | 1513.3ミリ秒 | 0.2186 | 0.9427 | 4.209 |

採用した設定は、比較した9通りのうち**平均絶対誤差と相関係数の両方で最良**であり、
かつ small の他の3通りより速い。

## なぜ small を選んだか

- tiny と base は速いが、毎秒モーラ数の平均絶対誤差が small より明確に大きい。
  ベースラインの役割は「モデルなしで到達できる上限」を示すことなので、
  精度の高い側を採る意味がある
- medium 以上は「小型版」という 3-3 の指定から外れ、所要時間も現実的でなくなる
- small は日本語の Common Voice に対して十分な精度が出ており、
  100件での平均絶対誤差は信号処理ベースライン（dev 全件 0.8961）の4分の1程度である

## 量子化しない理由

Apple Silicon（arm64）では、CTranslate2 の float32 経路が Accelerate の行列積を使うのに対し、
int8 経路は汎用の整数カーネルを通る。その結果、**この環境では int8 のほうが遅く、かつ精度も落ちた**
（上表の small int8 と small float32 を比較）。量子化は「速くするため」に行うものなので、
速くならない以上は採らない。設定で `compute_type` を切り替えられるようにはしてある。

## デバイスを cpu にした理由

- CTranslate2 は CUDA と CPU のみに対応し、**mps（Metal）に対応していない**。
  CLAUDE.md の「学習デバイスは mps」は学習に対する規則であり、
  本タスクの指示でも ASR は cpu でよいとされている
- ベースラインは学習を伴わないので、mps を使えないことによる不利益はない
- cpu 実行なので、CLAUDE.md の「MPS未対応演算でCPUフォールバック」に該当する事象は発生しない

## ビーム幅を1（貪欲）にした理由

beam_size=5 は1.4倍前後遅くなるが、100件での平均絶対誤差は改善しなかった
（上表を参照）。書き起こしの文字列としての質が上がっても、
モーラ数という粗い量にはほとんど効かないためと考えられる。速いほうを採る。

## VAD を使わない理由

`vad_filter` を有効にすると無音区間が除かれるが、毎秒モーラ数の分母には
**クリップ全体の長さ**を使う必要がある（正解のモーラ数がクリップ全体に対して与えられているため）。
VAD は分子（書き起こし）だけに影響するので、条件を揃える意味で無効にした。
信号処理ベースラインの無音の扱いと同じ考え方である。

## 評価の規模（dev 全件ではなく部分集合にした理由）

`scripts/run_asr_baseline.py timeit --size 30` で実測した結果は次のとおりである。

- 書き起こし＋モーラ計数: **741.6ミリ秒/クリップ**（実時間の7.00倍速）
- mp3 の復号と16kHzへの再標本化: 7.2ミリ秒/クリップ（別計上）

dev 全件は29,518クリップなので、逐次実行すると**約6.08時間**かかる見込みになった。
信号処理ベースライン（dev 全件を0.36分）と比べて桁違いに遅い。
そこで dev 全件ではなく、**固定シードで抽出した部分集合**で評価する。

| 項目 | 値 |
| --- | --- |
| 抽出元 | 検証セット dev（29,518クリップ） |
| 件数 | **5,000件**（dev の16.9%） |
| シード | **20260922** |
| 抽出方法 | `random.Random(20260922).sample(range(29518), 5000)` を昇順に並べたもの |
| 所要時間の見込み | 約62分 |

シードは、信号処理ベースラインのパラメータ調整に使ったシード（20260921、2,000件）と
**別の値**にしてある。

比較を成立させるため、**同じ部分集合で信号処理ベースラインも再評価**し、
`results/metrics.csv` に追記する。実験IDで部分集合であることが分かるようにする。

| 手法 | experiment_id |
| --- | --- |
| 書き起こし | `004-asr-baseline-subset5000-seed20260922` |
| 信号処理（同じ部分集合で再評価） | `003-envelope-baseline-subset5000-seed20260922` |

テストセット（`configs/splits/test.json`）は使っていない。
`spkrate.eval.runner` はテスト分割を渡されると例外を送出する。

## 1クリップあたりの処理時間の測り方

`results/metrics.csv` の `latency_ms_per_inference` は、`spkrate.eval.runner.evaluate` が
推定器の呼び出しだけを計測した値である。**mp3 の復号と再標本化は含まない**
（手法そのものの重さを信号処理ベースラインと同じ条件で比べるため）。
音声の復号は複数プロセスで先読みするが、音声認識は主プロセスで逐次実行するので、
並列化がこの値を歪めることはない。
