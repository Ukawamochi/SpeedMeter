## 0. 決めたこと

| 項目 | 決定 |
| --- | --- |
| 採用する方式 | **方式A**（クリップ全体を入力とし、クリップ全体のモーラ数を正解とする） |
| 方式B | **第5段階では実装しない**。第7段階7-2の探索条件として保留する。5節の移行条件のいずれかに該当した時点で着手する |

## 1. クリップ長の分布から読めること

### 1.1 測定されている値

| 項目 | 値 | 出所 |
| --- | ---: | --- |
| 平均クリップ長（残存295,179件の全数） | **4.630 秒** | `results/clip_filtering.md` 4節 |
| 平均クリップ長（無作為1,000件） | 4.631 秒 | `results/common_voice_overview.md` 6節 |
| 中央値（同1,000件） | **3.960 秒** | 同上 |
| 最小 / 最大（同1,000件） | **1.116 秒 / 13.320 秒** | 同上 |
| 平均フレーム数（train 100件、hop 10ms） | 465.0 フレーム（4.644秒） | `docs/decisions/004-feature-storage.md` |
| train の合計 | 236,143件 / 304.80時間 | `results/splits_overview.md` |
| dev の合計 | 29,518件 / 37.10時間 | 同上 |
| dev の帯別平均クリップ長 | 4未満 3.26秒 / 4-6 4.34秒 / 6-8 6.16秒 / 8以上 6.25秒 | `docs/experiments/002-baseline.md` 2節 |

全数平均（4.630秒）と1,000件標本の平均（4.631秒）が0.001秒しか違わないので、**この標本は長さについて代表性がある**と見てよい。
PLAN.md の4.467秒は版違いの値であり、以下は4.630秒を使う。2.0秒窓に対して**2.32倍**である。

### 1.2 不足している数値（未解決点。本タスクでは測定しない）

**クリップ長のヒストグラムおよび分位点（第1四分位・第3四分位・2.0秒未満の件数）はどの results にも無い。**
`results/common_voice_overview.md` 6節が持つのは最小・最大・平均・中央値・合計の5つだけである。
したがって「2.0秒未満のクリップが何件あるか」は**現時点で確定できない**。7節に未解決点として記録する。

参考として、最小1.116秒・中央値3.960秒・平均4.630秒から対数正規分布を当てはめた**推定値**を下表に示す。
これは測定ではなく仮定に基づく外挿であり、判断の主たる根拠には使わない。

| 範囲 | 推定割合 | 推定件数（295,179件中） |
| --- | ---: | ---: |
| 2.0秒未満 | 約11% | 約33,000 |
| 2.0〜3.0秒 | 約20% | 約59,000 |
| 3.0〜5.0秒 | 約33% | 約97,000 |
| 5.0〜8.0秒 | 約26% | 約77,000 |
| 8.0秒以上 | 約10% | 約31,000 |

当てはめの妥当性には限界がある。この分布は13.320秒超が1.5%（1,000件中15件）あることを含意するが、標本の最大は13.320秒だった。
**右の裾は実際にはこれより軽い**。平均と中央値を固定したまま右の裾を軽くすると左の裾も軽くなるので、
「2.0秒未満は約11%」は**上限に近い見積もり**であり、実際はこれより小さいと考えられる。

確実に言えるのは次の2点である。**(a) 2.0秒未満のクリップは存在する**（標本の最小が1.116秒）。
**(b) 中央値3.960秒なので、半数のクリップは2.0秒窓2個ぶんに満たない。**

### 1.3 2.0秒未満のクリップは、方式Aでは問題にならず方式Bでは損失になる

この非対称性が本決定の要点の1つである。

- **方式A**: 仕様のモデルは「フレームごとのsoftplus出力 → 時間方向の総和」であり、入力の時間長に制約がない。
  1.116秒のクリップも111フレームの入力として**そのまま学習に使える**。PLAN.md 5-1 も「入力の時間長が可変でも動作すること」を完了条件にしている。
  **2.0秒未満のクリップを1件も捨てない**
- **方式B**: 2.0秒の区間を切り出せない。2.0秒未満のクリップ（推定で最大11%、約33,000件）は**丸ごと使えない**か、
  詰め物で2.0秒に伸ばす必要がある。後者は「詰め物を含む窓」という学習にしか存在しない条件を作るので、方式Bが目的とする
  「学習と推論の条件を揃える」ことと矛盾する

さらに、拡張との組み合わせで差が開く。`docs/decisions/006-augmentation.md` の時間伸縮は0.7〜1.5倍で、適用確率0.5である。
**伸縮率0.7を引いたとき、2.0秒の窓を切り出すには元のクリップが2.857秒以上必要**になる。1.2節の推定では約28%のクリップが
この条件を満たさない。方式Aでは0.7倍で0.78秒になったクリップもそのまま学習できる。
時間伸縮は「学習データの毎秒モーラ数の分布を広げる唯一の手段」（006の2節）であり、
速い側（伸縮率0.7側）は目標値がもっとも厳しい8以上の帯に効く拡張なので、ここを削られるのは方式Bの実質的な不利になる。

### 1.4 方式Bの「データ量も増える」は、独立な情報の増加ではない

PLAN.md は方式Bの利点として「データ量も増える」を挙げる。内訳を数えると次になる。

| 数え方 | train での件数 | 備考 |
| --- | ---: | --- |
| クリップ（方式A） | 236,143 | 合計304.80時間 |
| 重なりなしの2.0秒窓 | 約548,600 | 304.80時間 ÷ 2.0秒。2.32倍 |
| 0.25秒刻みで切り出した窓（推論と同じ刻み） | 約270万 | 1クリップ平均11.5個。11.5倍 |

**合計音声時間は304.80時間のまま変わらない。**増えるのは切り出し位置の数であって、独立な情報量ではない。
0.25秒刻みの窓は隣同士が87.5%重なっており、1エポックで同じ音を8回見ることになる。
実質的な増分は「重なりなしで2.32倍」が上限であり、しかもその2.32倍は1件あたりの長さが2.32分の1になることと引き換えである。
一方、方式Bが確実に得るものは**窓境界での切断を学習時に経験できること**（2.3節）であって、データ量ではない。
利点の主張を正しく置き直すと、方式Bの価値は量ではなく条件の一致にある。

## 2. 仕様のモデル構造（フレームごとの出力の総和）が方式Aに与える意味

`docs/spec.md` のモデルは「周波数方向を圧縮する2次元畳み込み層 → 時間方向の膨張畳み込み層 → フレームごとのsoftplus出力 → 時間方向の総和」である。
この構造は、クリップ長と窓長の差を**かなりの程度まで吸収する**。理由を3つに分けて述べる。

### 2.1 出力は「局所的な話速の積分」であり、長さに依存する形をしていない

モデルは各フレーム t について非負の値 r(t) を出し、出力は Σ r(t) である。r(t) は「そのフレーム付近に存在するモーラの密度」と解釈できる。
クリップ全体で学習するとき損失が拘束するのは Σ_クリップ r(t) = N_クリップ だけだが、**取り出す区間を変えても同じ r(t) を足すだけ**なので、
r(t) が正しければ任意の2.0秒区間の推定は自動的に正しい。

これは「クリップ長4.63秒で学習したモデルを2.0秒で使う」という**尺度の不一致が原理的に存在しない**ことを意味する。
固定長入力から全結合層でスカラーを出す構造であれば、入力長を変えた時点でモデルが別物になり、方式Bが実質的に必須になっていた。
**仕様が総和構造を選んでいることが、方式Aを先に置ける最大の根拠である。**

### 2.2 受容野が有限なら、クリップ平均を一様に塗る解は表現できない

方式Aへの正当な懸念は「損失が拘束するのは総和だけなので、モデルが r(t) をクリップ内で好きに配置してよい」という点である。
最悪の解は、クリップ平均の話速を全フレームに一様に塗ることで、これだと総和は合うのに個々の2.0秒窓の値はクリップ平均しか返さない
（`docs/experiments/002-baseline.md` 3.4節の第二の指摘がこの状況を指している）。

しかしこの解は、**受容野がクリップ長より十分小さければモデルに表現できない**。
フレーム t の出力は t を中心とする受容野 R の範囲しか見られないので、クリップ全体の平均話速という大域量を知りようがない。
一方で同じ局所音響パターンはデータセット中の多数のクリップに現れ、それぞれ前後の無音の量も全体の話速も違う。
すべてのクリップで総和を合わせる唯一の整合的な解は、**r(t) が局所的に正しいこと**である。
これは弱ラベル学習（総和だけが与えられる計数問題）で標準的に効く論法であり、方式Aの成否はここに賭けている。

したがって第5段階に次の設計制約を課す。

- 受容野は**201フレーム（2.0秒）を超えてはならない**。超えると、窓1つの出力に窓の外の情報が必要という構造になり、推論時に再現できない
- 推奨は**51〜101フレーム（0.5〜1.0秒）**。平均クリップ長465フレームに対して11〜22%であり、2.2節の論法が働く余地が十分にある。
  同時に、長音・促音のような0.2〜0.5秒に及ぶモーラを1つの受容野で捉えられる
- 例: 2次元畳み込みの後段に、カーネル3・膨張率1,2,4,8,16の層を積むと受容野は63フレーム（0.63秒）になる
- 受容野を設定から算出してログと `config_snapshot.yaml` に記録する

### 2.3 吸収しきれないのは「窓の端」である

総和構造が吸収できない差が1つだけ残る。**境界の性質**である。

- 学習時（方式A）のクリップ境界は、ほぼ常に**発話の開始と終了**であり、前後は無音である
- 推論時の2.0秒窓の境界は、連続音声の**任意の位置**で切られる。モーラの途中で切れることが普通に起きる

受容野 R のモデルでは、窓の端から R/2 以内のフレームが詰め物の影響を受ける。窓201フレームに対して R=63 なら**約31%のフレーム**が該当する
（学習時のクリップ465フレームでは13%）。モデルが「詰め物の隣は無音である」という関係を学んでいると、
推論時に端で切られた発話を過小に数える。

大きさの見立て。窓の両端で d 秒ぶんを話速 ρ で取りこぼすと、誤差は 2dρ モーラ、毎秒モーラ数に直すと 2dρ/2.0 = dρ である。
平均話速 ρ=5.03（`results/clip_filtering.md`）として、d=0.05秒なら**0.25 mora/s**、d=0.1秒なら**0.50 mora/s** になる。
後者はクリップ単位の全体目標0.50そのものに等しく、**無視できる量ではない**。

ただし次の3点で緩和される。第一に、境界で切れたモーラは真の値も整数ではないので、誤差の一部は方式Bでも消えない（5節・6.2節）。
第二に、推論は0.25秒刻みで重なる窓を出すので、表示の時系列としては平滑化される。
第三に、受容野を小さく保てば d 自体が小さくなる。

**そして重要なのは、この量が第5段階にアライメント無しで直接測れることである**（4.3節のD1）。
測れる以上、先に方式Bを実装して防ぐ理由はない。測ってから決めればよい。

### 2.4 クリップ単位と窓単位の換算（002の記述の確認）

`docs/experiments/002-baseline.md` 3.4節は「クリップ単位評価は窓誤差を1.4〜1.7分の1に薄める」「クリップ0.50は窓単位0.7前後に相当」とする。
総和構造ではこれが式で確かめられる。クリップを k 個の窓に分け、各窓のモーラ数の誤差 e_w が独立で標準偏差 s とすると、
クリップのモーラ数の誤差は標準偏差 √k·s、毎秒モーラ数では √k·s/(2k) = s/(2√k)。窓単位の毎秒モーラ数の誤差は s/2 なので、比は **√k** である。
平均クリップ長4.630秒なら k=2.32、√k=**1.52** で、002の「1.4〜1.7」に収まる。クリップ単位0.50は窓単位0.76に対応する。

この換算が成り立つのは**誤差に偏りがない場合だけ**である。2.3節の端の取りこぼしは偏った誤差なので√kでは薄まらず、そのまま窓単位の誤差に乗る。
D1（4.3節）はまさにこの偏り成分を測る診断であり、閾値0.25 mora/s は窓単位目標0.76の3分の1として置いた。

## 3. 「順序を覆す理由」の候補と、その検討

PLAN.md の指示に従い、方式Bから始めるべき理由になりうる候補を列挙して検討した。

| # | 候補 | 検討 | 結論 |
| ---: | --- | --- | --- |
| 1 | クリップが2.0秒窓に対して短すぎ、方式Aの学習条件が推論と大きく違う | 平均4.630秒は窓の2.32倍。総和構造では尺度の不一致が原理的に生じない（2.1節）。中央値3.960秒でも窓2個ぶんに近い | 覆さない |
| 2 | 2.0秒未満のクリップの扱いが方式Aで破綻する | 逆である。方式Aは可変長入力なので1.116秒でもそのまま使える。捨てるのは方式Bの側（1.3節） | **方式Aを支持** |
| 3 | 方式Bのほうがデータ量が増えるので、先にやったほうが学習が安定する | 合計音声時間は304.80時間で不変。増えるのは重複した切り出し位置（1.4節）。236,143件・304.80時間は方式Aのままでも小型CNNに十分である | 覆さない |
| 4 | 窓境界での切断を学習で経験できないと、推論時に系統的な誤差が出る | これは実在する差である（2.3節）。ただし**大きさが未知**で、D1により第5段階でアライメント無しに測れる。測定前にコストの高い方式Bへ進むのは順序が逆 | 覆さない（ただし5節の第1条件にする） |
| 5 | 窓単位の目標値が002で未設定のままで、方式Aでは埋められない | 事実である。窓ごとの正解はアライメント無しには作れない。ただし002の判定6項目はすべてクリップ単位であり、5-4の判定は方式Aで実施できる。窓単位の目標が必要かは002自身が「第4段階の決定後に再検討」としており、D1〜D3の診断で代替できる範囲がある | 覆さない（7節に残す） |

加えて、方式Bを先に置くコストは小さくない。強制アライメントの導入（新規依存の可能性、236,143件への適用、誤りの検出基準の設定）は
**それ自体が1段階ぶんの作業**であり、しかも「どれだけ効くか」の見積もりを持たないまま着手することになる。
方式Aはベースライン2つと同じクリップ単位で評価でき（002の判定条件がそのまま使える）、比較の基準点を最短で作れる。

**結論: 順序を覆す理由は見つからなかった。方式Aを採る。**

## 4. 第5段階で作るもの（方式Aの具体）

### 4.1 データの与え方

| 項目 | 内容 |
| --- | --- |
| 1件の入力 | クリップ1件の全区間。16kHzモノラル波形 → 拡張 → 対数メル（80 × フレーム数）→ 正規化 |
| 1件の正解 | そのクリップの**モーラ数**（`data/processed/clips.jsonl` の値）。毎秒モーラ数ではない |
| 拡張 | `docs/decisions/006-augmentation.md` のとおり波形に適用。時間伸縮ではモーラ数は不変、長さのみ変わる（`mora_count_after_time_stretch`）。方式Aの正解はモーラ数なので**ラベルの読み替えが不要**である |
| 拡張なしの経路 | `data/processed/features/train`（事前計算特徴量）をクリップ単位に切り出して使う |
| 検証 | `data/processed/features/dev`。拡張はかけない |
| 評価 | クリップ単位。毎秒モーラ数 = 出力 ÷ クリップ長。002の判定6項目をそのまま適用する |

### 4.2 可変長を扱う実装上の必須事項

- **バッチ内の詰め物をマスクしてから総和をとる**。出力がsoftplusで常に正のため、詰め物のフレームを足すとモーラ数が水増しされる。
  これは損失が下がりながら静かに壊れる種類の誤りなので、必ず明示的に除く
- **同じクリップに詰め物を足しても出力が変わらないことを単体テストで固定する**（詰め物0・100・500フレームで出力が一致すること）。
  畳み込みが詰め物の領域をまたいで値を持ち込む経路も同時に塞がる
- 長さの近いものを集めてバッチにし、詰め物の総量を減らす。クリップ長は1.1〜13.3秒（最大12倍）あるので、長さを見ずに組むと無駄が大きい
- 受容野を設定から計算して記録し、201フレームを超える設定を拒否する

### 4.3 5-4で同時に記録する3つの診断（アライメント不要）

いずれも正解ラベルを必要とせず、方式Aのまま測れる。5節の移行条件はこの3つを使う。

| 記号 | 診断 | 手順 | 出力する数値 |
| --- | --- | --- | --- |
| **D1** | 分割整合性 | dev から4.0秒以上のクリップを無作為1,000件。先頭から重なりなしに2.0秒窓を m=floor(T/2.0) 個とり、各窓を単独で推論した値の総和 Σ と、同じ 2.0m 秒の区間を一括で推論した値 P を比べる | `mean(|Σ − P|) / (2.0m)`（mora/s） |
| **D2** | 無音・雑音窓の出力 | デジタル無音の2.0秒窓500本と、MUSAN noise のみの2.0秒窓500本を推論する。仕様は「無音は0モーラ」 | 予測モーラ数の平均（mora） |
| **D3** | 連結加法性 | dev から2件ずつ500組を連結（間に0.2秒の無音）し、`P(AB)` と `P(A)+P(B)+P(無音)` を比べる | `mean(|差|) / 連結後の長さ`（mora/s） |

D1が2.3節の端の取りこぼしを直接測る主要な診断である。D2は「無音にも話速を塗っていないか」（2.2節の最悪解の検出）、
D3はD1の逆向き（結合したときに壊れないか）を見る。D2・D3は補助とする。

参考として、devをクリップ長で層別（2.0秒未満 / 2.0〜3.0 / 3.0〜5.0 / 5.0〜8.0 / 8.0秒以上）したMAEも記録する。
ただしクリップ長と話速には相関がある（002の2節: 4未満の帯は平均3.26秒、8以上の帯は6.25秒）ため、
層別MAEの差は入力長への依存と話速分布の違いが混ざる。**単独では移行の根拠にしない。**

## 5. 方式Bへ移る条件

次のいずれかに該当した時点で、方式Bを第7段階7-2の1条件として実装する。該当しなければ実装しない。

| # | 段階 | 条件 | 閾値の根拠 |
| ---: | --- | --- | --- |
| **B1** | 5-4 | **D1 > 0.25 mora/s** | 端の切断による偏りはクリップ単位評価では√kで薄まらず、窓単位の誤差にそのまま乗る（2.4節）。窓単位の目標0.76（= クリップ0.50 × 1.52）の3分の1を超える偏りが1つの原因から出ているなら、窓ごとのラベルで直接押さえるべきである |

| **B4** | 7-1 | **窓長1.0秒の条件を実施すると決めた場合** | 学習側に窓長という概念が存在するのは方式Bだけである。方式Aには窓長の設定項目が無い。なおこれは `docs/spec.md`「モデルの入力単位: 固定長窓2.0秒」の変更にあたるので、**人間の承認が先に要る** |
| **B5** | 5-4 / 7-2 | D3 > 0.25 mora/s が D1 と同時に成り立つ | D1の裏付け。単独では移行の根拠にしない |

それでも不足と判断された場合のみ第9段階9-3（文単位の実環境評価）の結果を見て再検討する。

### 6.2 窓ごとの正解の定義（7-2で決める必要がある）

アライメントは各モーラ i に区間 [s_i, e_i] を与える。窓 [t, t+2.0] のモーラ数には2通りの定義がある。

- **(a) 中心時刻による計数**: `(s_i + e_i)/2` が窓内にあるモーラを1と数える。整数値になる
- **(b) 重なりによる按分**: `|[s_i, e_i] ∩ [t, t+2.0]| / (e_i − s_i)` を足す。小数値になる

仕様の出力は「非負の連続値」なので (b) を既定とし、(a) を対照として同時に測ることを推奨する。
(b) は窓を0.25秒ずらしたときの正解の変化が連続になるという利点があるが、「モーラの重みが継続時間に一様に分布する」という仮定を置く
（長音には妥当、破裂音には妥当でない）。**この差はどちらが正しいかを机上で決められないので、7-2で両方を試す。**
なお2.3節で述べたとおり、窓境界で切れたモーラの扱いは真の値そのものが曖昧であり、方式Bでもこの曖昧さは消えず、定義を固定するだけである。

### 6.3 アライメントの誤りの検出（すべて聴取なしで判定できる）

| # | 検査 | 判定 |
| ---: | --- | --- |
| 1 | CTC経路のフレーム平均対数尤度 | train 全体の分布をとり、**下位1%**を除外候補にする |
| 2 | モーラ継続長の上限 | 長音「ー」・促音「ッ」・撥音「ン」は **1.0秒**、それ以外は **0.6秒** を超えたら異常。1つでも含むクリップを除外候補にする |
| 3 | モーラ継続長の下限 | **30ミリ秒**未満のモーラが全体の20%を超えるクリップを除外候補にする（記号列を時間軸に押し込めた失敗の兆候） |
| 4 | 整合性の検算 | アライメントのモーラ数が `count_mora(原文)` と一致すること。不一致は実装の誤り |
| 5 | 被覆 | 先頭モーラの開始が0未満、末尾モーラの終了がクリップ長超なら実装の誤り。先頭の開始が2.0秒超、または末尾の終了がクリップ長−2.0秒未満のものは、前後の無音が長いか整列失敗として個別に確認する |
| 6 | 発話区間の密度 | 先頭モーラの開始から末尾モーラの終了までの長さで割った毎秒モーラ数が **1未満または12超**なら除外。`results/clip_filtering.md` の外れ値の閾値と同じ値を使い、基準を一貫させる |
| 7 | 無音との矛盾 | 短時間実効値が発話区間の中央値より25dB以上低いフレームに中心が置かれたモーラの割合が **5%** を超えたら除外候補 |
| 8 | 独立した照合 | 既存の包絡法（`src/spkrate/baselines/envelope.py`）が検出する音節ピークの時刻、または faster-whisper の単語時刻とつき合わせる。ピークがどのモーラ区間にも入らない割合が高いクリップを疑う。閾値は分布を見て決める |
| 9 | 聴取による抜き取り | **行わない**（CLAUDE.md の禁止事項）。必要と判断した場合は第6段階6-3と同じ枠で人間に依頼する |

除外率の目標は事前に置けない。1〜8を適用した結果の除外率を `results/` に記録し、**5%を大きく超える場合はアライメントの手段自体を見直す**。
