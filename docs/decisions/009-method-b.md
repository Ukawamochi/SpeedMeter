### 1.2 窓の取り方（単一クリップ）

| 項目 | 実装 | 種別 |
| --- | --- | --- |
| 対象 | 一覧のうち長さ32,000標本以上のクリップ（件数 N_single）。32,000標本ちょうどは開始0の1通り | 根拠: 指示書「2.0秒未満のクリップは連結の中でだけ使う」、dev_window の「窓全体が収まるものだけ」 |
| 1エポックの窓の数 | 各クリップから1窓（計 N_single） | 根拠: 指示書 |
| 窓の位置 | 標本単位の整数一様乱数。伸縮後の音源長 N' に対し開始 w ∈ {0, 1, …, N' − 32000}（両端を含む） | 既定の選択。0.25秒刻みは推論の間隔であって、学習では窓の位置を連続にずらした方が境界での切れ方を網羅できる。按分の正解は任意の位置で計算できる |
| 乱数 | 件ごとに `default_rng((seed, epoch, index))`（`WaveformClipDataset` と同じ流儀）。位置・伸縮率・拡張をこの1つの生成器から順に引く | 既定の選択。エポックを指定すれば再現でき、再開時も同じになる |

### 1.3 連結

| 項目 | 実装 | 種別 |
| --- | --- | --- |

| 連結に使うクリップ | 一覧の全クリップ（2.0秒未満を含む）。一覧で3件未満の話者と、端数（1〜2件）は dev_window と同じく使わない（2.0秒未満でこれに当たるクリップは学習に使われない。件数を記録する） | 根拠: dev_window と同じ規約 |
| 組の作り直し | **エポックごとに作り直す**。エポック e では種 (seed, e, 0xC0CA7, p) で p = 0, 1, 2, … 回目の組の作成を繰り返し、組の総数が N_single 以上になったら、全組から `default_rng((seed, e, 0xC0CA7, 0x5E1EC7))` で N_single 組を非復元抽出する | 既定の選択。1回の作成でできる組は約（一覧の件数 ÷ 4）で N_single より少ないため、1対1にするには複数回の作成が要る（1エポックに各クリップが約4回、別々の組で現れる）。エポックごとに組と無音長が変わる方が、同じ組を繰り返し見るより多様である |
| 1組あたりの窓 | 1窓。位置は1.2節と同じく連結音声全体（伸縮後）の一様乱数 | 根拠: 指示書「連結した音声からも窓を切り出す」。1組1窓にすれば件数の比が窓の数の比に一致する |
| 比率 | 1エポックの連結の窓の数＝N_single（1対1）。データセットの長さは 2 × N_single（＋無音サンプル）で、エポック間で一定 | 根拠: 指示書「比率は1対1」 |
| 正解 | 各クリップのモーラ時刻を、連結音声内のそのクリップの開始標本（`WindowSource.offsets`）だけずらし（`source_moras` と同じ）、1.1節と同じ按分で数える。無音部分は0 | 根拠: dev_window と同じ定義 |
| 波形の組み立て | 連結音声の全体は作らない。窓（と1.4節の余白）に重なるクリップだけを読み、間の無音を全標本0で埋めて抜粋を作る。窓の位置は、アライメントの長さから求めた標本数だけで決まるので、読む前に決められる | 既定の選択。連結音声は平均で約20秒（最長は dev で56秒）あり、組の全クリップを毎回読むと1エポックの読み込み量が方式Aの数倍になる。重なるクリップは平均2件に満たない |
| エポックの区切りでの作成場所 | `set_epoch` で主プロセスが組を作る。DataLoader のワーカーは既定（非永続）なのでエポックごとに最新の状態が渡る | 根拠: 既存の `set_epoch` の呼び出し（train.py）と `persistent_workers` を使っていないこと |

### 1.4 拡張と時間伸縮

005 6.4節の「適用順は拡張 → 窓の切り出し」と 006 の拡張の順（時間伸縮 → 残響 → 雑音 → 帯域制限 → 音量）を保ち、拡張を掛ける範囲を「窓の前後に余白を付けた抜粋」にする。

| 手順 | 実装 | 種別 |
| --- | --- | --- |
| 1. 伸縮率 | 確率0.5で伸縮する（exp004 と同じ `AugmentConfig` の既定値）。伸縮率 s は一様乱数だが、下限を max(0.7, 32000 / N) にする（N は音源の標本数）。伸縮しない場合 s = 1 | 下限の引き上げは既定の選択。s < 32000 / N だと伸縮後の音源が2.0秒に満たず窓を切れない（2.0〜2.86秒のクリップで起こる）。引き直しや s = 1 への置き換えより、範囲内の一様分布を保つ方が伸縮率の分布の歪みが小さい。N ≥ 32000 なので下限は1.0以下で、上限1.5と必ず両立する |
| 2. 窓の位置 | 伸縮後の音源長 N' = round(N · s) に対し、w を 0〜N' − 32000 の一様整数で引く | 1.2節 |
| 3. 抜粋 | 元の時刻で [w / s − 余白, (w + 32000) / s + 余白] を音源の範囲に切り詰めた区間（開始標本 a）を組み立てる。余白は元の時刻で0.5秒 | 既定の選択。位相ボコーダの端の影響（窓1024点＝64ミリ秒）と残響の尾（RT60 は最大0.7秒、0.5秒後には約−43dB）を窓の外で吸収する |
| 4. 伸縮 | 抜粋に `time_stretch(抜粋, s)` を掛ける（出力長 round(M · s)） | 根拠: 既存関数 |
| 5. 時刻の変換 | モーラ時刻 t（音源内、秒）を t' = (t − a / 16000) · s に変換する | 根拠: 指示書「モーラの時刻を伸縮率に合わせて変換してから窓の正解を計算」。005 6.4節「位相ボコーダは時間軸を線形に伸ばすのでモーラ時刻は一律 × stretch」 |
| 6. 残りの拡張 | 伸縮後の抜粋に `augment_waveform`（`time_stretch_enabled=False` にした設定）で残響・雑音・帯域制限・音量を掛ける。雑音は MUSAN noise の学習用（`configs/splits/musan_noise.json` の train）。SNR の基準は抜粋の実効値 | 根拠: 指示書「雑音・残響・音量・帯域制限は時刻を変えない」、0節「MUSAN noise の学習用の分割だけ」。SNR の基準は既定の選択（下記の注） |
| 7. 切り出し | 抜粋内の窓の開始 k = w − round(a · s) を [0, 出力長 − 32000] に収め、k から32,000標本を切る | 丸めで1標本ずれても、正解は実際に使った k で計算するので食い違わない |
| 8. 正解 | 変換後の時刻 t' と窓 [k / 16000, k / 16000 + 2.0) で `window_mora` | 1.1節 |
| 9. 特徴量 | 対数メル → 正規化 → 周波数マスク（exp004 と同じ `augment_feature_with_status`。時刻を変えない） | 根拠: exp004 と同じ拡張 |

- 伸縮なし（s = 1）の窓の波形は、元の音源（単一または連結）の [w, w + 32000) と一致する（拡張を掛ける前の段階で）。単体テストで確かめる
- 注（SNR の基準）: dev_window の雑音下の版は音源全体の実効値を基準にする。学習では抜粋（約3秒）の実効値を基準にするので、発話の少ない抜粋では雑音が相対的に小さくなる。exp004 も「入力単位（クリップ）の実効値」を基準にしており、学習の入力単位を基準にする点は同じである。音源全体の実効値を得るには組の全クリップを読む必要があり、1.3節の読み込みの節約と両立しないため、この差は受け入れて記録にとどめる
- 伸縮の適用率・伸縮率・窓の種類（単一/連結）・正解0の窓の割合・帯別の件数をエポックごとに `metrics.jsonl` と log.txt に記録する（タスク5で8以上の帯と正解0の窓を読むため）

## 2. 決めた細部の要約

1. 窓の位置は伸縮後の音源上の標本単位の一様整数（両端を含む）
2. 連結の組はエポックごとに作り直し、1エポックに N_single 組（複数回の組の作成から非復元抽出）。1組1窓
3. 時間伸縮は窓の前後に0.5秒の余白を付けた抜粋に掛けてから窓を切る（拡張 → 切り出しの順）。伸縮率の下限は max(0.7, 32000 / N)
4. 雑音の SNR の基準は抜粋の実効値（dev_window の雑音下の版は音源全体。差は記録にとどめる）
5. 無音サンプルは exp004 と同じ設定値。学習入力の長さ（2.0秒）から長さを取るので全件2.0秒。件数は 0.03 × 2N_single
6. 検証は主指標の窓から種 20260928 で50,000窓を単純無作為抽出し、特徴量を float16 で一度だけ保存
7. 正規化の値は作り直さない。bucketing は使わない

## 3. spec.md に反映する文案（方式Bの学習時の窓の正解の定義）

「学習データ」節の末尾に次の小節を加え、冒頭の「データ拡張」の項と無音サンプルの表の `duration_range_sec` の行に下記の注を加える（タスク1の後半で反映する）。

> ### 方式B（窓単位の正解）での学習の窓と正解
>
> 方式B（docs/decisions/005-window-strategy.md 5節・6節、docs/directives/2026-09-26.md タスク3）で学習するときの入力と正解の定義。設計の確認は docs/decisions/009-method-b.md。
>
> - 対象: 学習に使うクリップの一覧（アライメント失敗・モーラ数の不一致・端の孤立・無発話疑いを除いたもの。results/train_alignment.md）と、train のアライメント（`data/processed/alignments/train.jsonl`）
> - 入力: 2.0秒（32,000標本）の窓。1エポックの入力は、(1) 長さ2.0秒以上の各クリップから1窓（単一）、(2) 同じ件数の連結の窓、(3) 無音・雑音のみのサンプル（正解0。件数は (1)+(2) の3%、長さ2.0秒）からなる。単一と連結の比率は1対1（測定に基づかない）。2.0秒未満のクリップは連結の中でだけ使う
> - 連結: 同一話者の3〜5件を0.3〜1.5秒の無音（全標本0。0.01秒単位）を挟んで連結する。組の作り方は dev_window（「窓単位の評価」節）と同じ手順で、乱数の種にエポック番号を加えてエポックごとに作り直す。1回の作成では各クリップを高々1回使い、組が単一の窓の数に達するまで作成を繰り返してから、その数だけ非復元抽出する。1組から1窓を切る
> - 窓の位置: 音源（時間伸縮の後）の中に窓全体が収まる開始位置から、標本単位の一様乱数でエポックごとに選ぶ
> - 正解: 窓 [t, t + 2.0) のモーラ数を dev_window と同じ按分（`spkrate.eval.dev_window.window_mora`）で計算する。モーラ区間は train のアライメント。連結では各クリップのモーラ時刻を連結音声内の開始位置だけずらす。計算は float32
> - 時間伸縮: 伸縮率 s（長さの倍率）で伸縮した音声では、モーラ時刻 t を t · s（抜粋の開始を原点にした時刻で）に変換してから窓の正解を計算する。したがって窓のモーラ数は伸縮で変わる（クリップ全体のモーラ数は不変）。伸縮後の音源が2.0秒に満たない伸縮率は使わない（下限を max(0.7, 2.0 ÷ 音源長) とする）。雑音重畳・残響・音量変化・帯域制限・周波数方向のマスクは時刻を変えないので、正解を変えない
> - 拡張の範囲と順序: 窓の前後に0.5秒（伸縮前の時刻）の余白を付けた抜粋に「時間伸縮 → 残響 → 雑音 → 帯域制限 → 音量」を掛けてから窓を切る。雑音の SNR は抜粋の実効値に対する比
> - 検証: dev_window の clean・主指標の窓から、種 20260928 で50,000窓を非復元抽出したもの。毎エポックの検証と早期終了（上限30エポック、5エポック改善なしで停止、指標は毎秒モーラ数の MAE）に使う

冒頭「データ拡張」の項への注（案）: 「時間伸縮の『モーラ数は不変』はクリップ全体についての記述である。方式Bの窓の正解は、時刻を変換してから数え直す（『学習データ』節の方式Bの小節）」

無音サンプルの表の `duration_range_sec` の行への注（案）: 「`null` は学習入力の長さの分布から復元抽出する。方式Aでは学習クリップの長さ、方式Bでは全件2.0秒になる」

## 4. 実装サブエージェントに付けさせる単体テスト

### 4.1 窓の正解の計算

1. 伸縮なしの単一クリップ: 任意の開始 w の窓の正解が `window_mora(開始, 終了, [w / 16000], 2.0)` と一致する（dev_window と同じ関数・同じ値）
2. 保存則: クリップを重なりなく覆う窓の正解の和が、覆った範囲に含まれる全モーラ数と一致する（按分の性質。伸縮ありでも成り立つ）
3. 点のモーラ（end <= start）: 窓の内側なら1、端 t + 2.0 ちょうどなら0
4. 窓の位置の範囲: 開始は0以上 N' − 32000 以下で、両端が実際に選ばれうる（小さい N' で全数を確かめる）。32,000標本ちょうどのクリップでは開始0だけ
5. 出力: 波形は32,000標本・特徴量は201フレーム、正解は float32 で0以上かつ音源の全モーラ数以下、`duration_sec` は2.0
6. 時刻を変えない拡張（残響・雑音・帯域制限・音量・周波数マスク）の有無で、同じ乱数の窓の正解が変わらない

### 4.2 時刻の変換

1. s = 1 では変換が恒等（抜粋の開始のずれだけ）で、窓の波形が元の音源の [w, w + 32000) とビット一致する（拡張前）
2. 線形性: s = 0.7・1.0・1.5 で、変換後の時刻で数えた窓の正解が、元の時刻の対応区間 [a / 16000 + k / (16000 · s), その開始 + 2.0 / s) を同じ按分で数えた値と一致する（按分は時刻の線形変換で不変。float32 の許容誤差内）
3. 実音での確認: 既知の時刻にクリック（短いパルス）を置いた合成音に抜粋の切り出しと `time_stretch` を掛け、出力でのピーク位置が変換後の時刻と一致する（許容は位相ボコーダの刻み程度、例えば20ミリ秒以内）
4. 伸縮率の下限: N が32,000〜45,714標本（2.0〜2.86秒）の音源で、引いた s が常に max(0.7, 32000 / N) 以上1.5以下で、窓が必ず切れる
5. 丸め: 抜粋内の開始 k は [0, 出力長 − 32000] に収まり、正解は実際に使った k で計算されている（k を1標本ずらすと正解もそれに応じて変わることを確かめる）

### 4.3 連結の生成

1. 組: 各組は同一話者の3〜5件、無音長は0.3〜1.5秒で0.01秒の倍数、1回の作成の中で各クリップは高々1回
2. 再現性: 同じ (seed, epoch) で同じ組・同じ窓、別の epoch では組が変わる
3. 比率: 1エポックの連結の窓の数が単一の窓の数と等しく、データセットの長さがエポック間で一定
4. 2.0秒未満のクリップは単一の窓に現れず、連結の組には現れうる。一覧で3件未満の話者のクリップは組に現れない
5. 時刻のずらし: 連結の窓の正解が、各クリップの時刻をオフセットだけずらして数えた値と一致する。無音だけに掛かる窓（クリップ自身の無音と挟んだ無音）は0。クリップの境界をまたぐ窓の正解は、両側のクリップの寄与の和
6. 部分の組み立て: 窓に重なるクリップだけから作った抜粋が、組の全クリップを連結した音声の同じ範囲とビット一致する（拡張なし）
7. 既存の互換: `build_concat_groups` に整数の種を渡したときの結果が拡張前と同じ（`tests/test_dev_window.py` が通る）

### 4.4 その他

1. 無音サンプル: `duration_range_sec: null` のとき全件2.0秒で、件数が round(0.03 × 2N_single)
2. 検証の抽出: 50,000件（小さい母集団では指定件数）が重複なし・昇順・すべて主指標の窓（known_no_speech・no_speech_suspect の由来でない）・種に対して決定的
3. アライメントの長さと読み込んだ波形の長さが違うクリップで停止する。test.json を指定すると拒否する
