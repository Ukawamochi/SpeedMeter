# 特殊拍の多い窓の損失の重みを上げる（exp020。docs/directives/2026-09-30.md タスク3）

- 判定日: 2026-09-30
- 読んだ資料: `CLAUDE.md`、`docs/directives/2026-09-30.md`（タスク3、「評価と判定」）、`results/special_mora_analysis.md`、`scripts/special_mora_analysis.py`、`docs/spec.md`（「損失」、方式Bの窓と正解）、`docs/decisions/009-method-b.md`・`011-fast-window-sampling.md`・`012-no-noise-on-strong-stretch.md`、`src/spkrate/train/method_b.py`、`src/spkrate/train/train.py`、`src/spkrate/labels/mora.py`、`configs/exp016.yaml`

## 1. 目的

results/special_mora_analysis.md で、特殊拍（長音「ー」・撥音「ン」・促音「ッ」）の割合が高い窓ほど過小評価が大きいことが4帯すべてで確かめられた（exp005、割合0.1あたり 8以上で −0.188 mora/s、exp016 は −0.211）。損失で特殊拍の割合が高い窓の重みを上げ、この傾きを抑えられるかを exp020（exp016 + 本設定）で確かめる。013（experiments）8節の #6（損失の変更）は、本タスクに限って行う（指示書タスク3の人間の承認）。

## 2. 決めたこと

| 項目 | 決定 |
| --- | --- |
| 設定のキー | `train.special_mora_weight_alpha`（α。既定 `0.0` で無効）と `train.special_mora_weight_max`（生の重みの上限。既定 `3.0`） |
| 使える条件 | `data.source: windows`（方式B）かつ `loss: mse`。他で α > 0 なら学習開始前に止める |
| 窓の特殊拍の割合 r | 按分後の特殊拍のモーラ数 ÷ 按分後の総モーラ数（窓の正解）。按分は正解と同じ `window_mora`（伸縮後の時刻で、各モーラの窓内の割合 f を足す）。特殊拍の判定はアライメントの `kana` が `ー`・`ン`・`ッ` の1文字（scripts/special_mora_analysis.py の `classify_mora` の `special` と同じ。拗音は特殊拍に含めない） |
| 正解の小さい窓 | 正解が 1.0 モーラ（毎秒0.5）未満の窓（正解0の窓を含む）は r = 0。分析の `--min-true-mora` の既定と同じ。正解の小さい窓では端で切れた特殊拍1つで r = 1 になり、重みが上限に届くため |
| 無音・雑音のみのサンプル | r = 0（生の重み1。正規化で他と同じく割られる） |
| 重みの形 | 生の重み w_raw = min(1 + α · r, 上限)。α = 5、上限 3.0 を exp020 の値とする（3節） |
| 正規化 | **バッチ内**で平均1: w = w_raw ÷ mean(w_raw)（無音サンプルを含むバッチの全件）。損失は mean(w · (予測 − 正解)²)（4節） |
| 無効のとき | 重みを計算せず、損失は従来の `torch.nn.functional.mse_loss` のまま。値と乱数の系列は変わらない |
| 検証の損失 | 重みを掛けない（`val_loss` は従来どおり） |
| 割合の求め方 | 学習の読み込み時（`load_train_clips(..., with_special=True)`）に、アライメントの `kana` からモーラごとの特殊拍の印（bool 配列、約580万モーラ）を1回だけ作り、窓ごとに正解と同じ計算で数える。train.jsonl は元から読み込み時に全行を解いているので、別のキャッシュファイルは作らない（遠隔機でも追加のデータは要らない）。乱数は使わない |
| spec.md | 「損失」の項に注を加えた（新しい実験の設定でだけ有効、既定は無効） |

## 3. 重みの強さの根拠

- **大きさ**: 8以上の帯で、特殊拍の割合0.1あたり約 −0.19 mora/s（話速を揃えた偏り。exp005）。割合0.05未満の窓（揃えた偏り +0.19）と0.30以上の窓（−0.48）の差は 0.67 mora/s。つまり**低い割合の窓は過大、高い割合の窓は過小**で、二乗誤差の勾配は両者で逆向きに打ち消し合っている。高い割合の窓の勾配を相対的に強めれば、打ち消しの釣り合いが高い割合の側へ動く（効く大きさは推測で、exp020 の測定で確かめる）
- **判定に要る変化**: 「改善」は 8以上の傾きの絶対値が 0.039（exp005 と exp007 の差 0.013 の3倍）以上小さくなること。exp016 の −0.211 に対して約2割の変化で、弱すぎる重みでは種の揺れと区別できない
- **α = 5**: 割合 0（生の重み1）に対し、分布の中央（0.10）で 1.5、上位10%（0.25）で 2.25、上位5%（0.30）で 2.5 倍になる。偏りの符号が変わる 0.1〜0.15 付近を境に、過小の大きい 0.2 以上の窓（約20%）を割合0の窓の2倍以上に重くする。α = 3 では 0.30 で 1.9 倍にとどまり、上の2割の変化を得るには弱いと考えた。α = 8 では 0.25 で上限に届き（窓の約11%）、偏りが最も大きくなる 0.2〜0.3 以上の区間で重みが区別できなくなる
- **上限 3.0**: α = 5 で割合 0.4 以上（窓の約1.5%）に掛かる。割合の非常に高い窓は、長い「ー」が窓の大半を占める窓や、ラテン文字の読み（「エー」「ダブリュー」。分析の感度分析でラベルの読みが話者と違う疑いがある）を含む窓で、少数の窓に重みが集中するのを防ぐ
- **有効な標本数**: α = 5・上限3 で、重みの2乗平均から求めた有効な標本の割合 (Σw)² / (N Σw²) は約0.91（α = 3 で 0.95、α = 8 で 0.88。4節の抽出による）。1割程度の実質的な減少で、学習の揺れを大きく増やさない範囲と判断した

## 4. 正規化をバッチ内にした理由

- **学習率と勾配の上限の実質を毎回そろえるため**: 生の重みのバッチ平均は、バッチ64・無音サンプル3%で 1.35〜1.76 と振れる（4節）。学習データ全体の平均（約1.55）で割る方式では、バッチごとの重みの平均が 0.87〜1.14 と振れ、`grad_clip: 5.0`（勾配のノルムの絶対値）に掛かる割合や1歩の大きさが、重みのない学習（exp016）と揃わない。バッチ内で割れば、どのバッチでも重みの平均はちょうど1になる
- **事前の見積もりが要らないため**: 速い窓の選び直し・伸縮率の抽選で窓の分布はエポックごとに変わる。全体の平均を前もって求めて固定すると、エポックによって平均が1からずれる
- **代わりに**: 1つの窓の重みが同じバッチの他の窓に依存する（生の重みのバッチ平均の振れで約 ±13%）。窓の順序はエポックごとに混ぜられるので、系統的な偏りにはならないと考えた
- 上限は生の重みに掛けるので、正規化後の最大は 上限 ÷ バッチの生の重みの平均 で、上限をわずかに上回りうる（抽出では最大 2.14）

## 6. 集計（log.txt と metrics.jsonl）

- 方式Bのエポックの窓の集計（`WindowEpochStats`。無音サンプルを除く）に加えた項目（既存の項目の値は変えない。重みが無効でも割合は集計する）:
  - `window_special_ratio_mean`: 窓の特殊拍の割合の平均
  - `window_special_ratio_bin00`〜`window_special_ratio_bin09`: 割合の0.1刻みの区間 [0, 0.1)、…、[0.9, 1.0] の窓の割合（1.0 は最後の区間）
  - `window_loss_weight_mean`・`window_loss_weight_max`: 窓の損失の重み（正規化後）の平均・最大。無効なら1
- 学習の全件（無音サンプルを含む）: `train_loss_weight_mean`（有効なら1になる）・`train_loss_weight_max`。無効なら1
- log.txt の「窓の集計」の行の末尾に「特殊拍の割合の平均=… 特殊拍の割合の分布(0.1刻み)=…/… 損失の重み(平均/最大)=…/…」、学習開始時に「特殊拍の多い窓の損失の重み: 有効 w = min(1 + 5 × 特殊拍の割合, 3) ÷ バッチ内の平均」（無効なら「なし」）
- `train_loss` は重み付きの値（平均1なので尺度は同じだが、exp016 の値とそのまま比べるものではない）。比べる指標は検証の値（`val_loss` と毎秒モーラ数の MAE。重みなし）

## 7. 副作用の見込み（exp020 の読み方）

1. **無音サンプルと割合0の窓の重みが下がる**: 正規化で、無音サンプル（3%）と割合0の窓の重みは約0.64になる。正解0の窓・MUSAN noise への出力（D2、014 の無音・雑音の窓）が悪化する恐れがある。exp016 と並べて確かめる
2. **割合の低い窓の過大が増える可能性**: 割合0.05未満の窓は 8以上で既に +0.19 の過大である。高い割合の窓に引かれて出力全体が上がると、傾きは小さくなっても、割合の低い窓の過大と全体の偏りが増える。傾きと一緒に、帯ごとの偏りと clean の MAE を見る
3. **ラベルの疑わしい窓の影響の増大**: ラテン文字の読みを含むクリップは長音を多く含み、ラベルの読みが話者の読みと違う疑いがある（分析の感度分析）。そうした窓の重みが上がる。評価の特殊拍の集計はラテン文字を除いた感度分析も並べるとよい
4. **帯の釣り合い**: 帯ごとの割合の平均はほぼ同じ（5節）なので、帯の間の重みの配分はほとんど変わらない
5. **学習の揺れ**: 有効な標本の割合が約0.91になり、1回の学習の揺れはわずかに増える。差は exp005 と exp007 の差（8以上の傾き 0.013）と比べて読む
6. **計算量**: 窓ごとに特殊拍のモーラだけで按分を1回足すだけで、学習時間はほぼ変わらない
