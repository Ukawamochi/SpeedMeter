# 統括Agentへの指示（2026-09-26 RTX3060の計算機の導入）

この文書はリポジトリ所有者（人間）の指示である。学習に使う計算機として、Mac（MacBook Air M5、mps）に加えて、sshで接続できるUbuntuの計算機（RTX3060 12GB、Core i7 第13世代、RAM16GB）を導入する。本書は、docs/directives/2026-09-26.mdの実行中に割り込む指示であり、本書のタスクを先に行う。2026-09-26.mdの残りの作業（exp005の完了待ち、評価、タスク5の判断）は、本書のタスク4で示す形に変えて続ける。

本書とCLAUDE.md、docs/plan.md、既存の指示書が矛盾する場合は本書を優先する。サブエージェントへの委譲、1コミット1論点、progress.mdへの記録などの運用規則は引き続き適用する。

本書をコミットしてから作業を始める。

## 0　人間の決定

1. 学習に使う計算機を2台にする
   - mac: 作業の本拠地。git、docs、results、metrics.csvの正本はこのMacのリポジトリだけに置く。デバイスはmps
   - ubuntu-desktop: 学習と推論を実行するだけの計算機。Macから「ssh ubuntu-desktop」で接続できる（パスワードなしで接続できる設定は人間が済ませた）。デバイスはcuda
2. 学習デバイスはmpsまたはcudaとする。CLAUDE.mdの「学習デバイスはmps」を改める。これは人間による規則の変更の指示である
3. cudaで学習する場合も、float64、torch.compile、混合精度（float16・bfloat16での学習）は使わない。TF32も無効にする（torch.backends.cuda.matmul.allow_tf32とtorch.backends.cudnn.allow_tf32をFalseにする）。mpsのfloat32と精度の条件をそろえるためである
4. 推論時間の測定は、これまでの値と比べられるよう、引き続きMacだけで行う
5. 並列の方針
   - 互いに依存しない学習は、2台で同時に実行してよい。1台で同時に実行する学習は1つまでとする。ubuntu-desktopはRAMが16GBで、波形の読み込みと拡張をCPUで行うためである
   - 評価（推論）は、学習中でない計算機で実行してよい。評価の結果は、どちらで実行してもMacのresults/とmetrics.csvに書く
   - metrics.csv、progress.md、questions.md、docs/への書き込みと、gitの操作は、Mac上の統括Agentだけが行う。ubuntu-desktopではコミットしない
6. 現在Macで学習中のexp005は止めない。exp006はubuntu-desktopで、exp005と並行して学習する

## タスク1　ubuntu-desktopの確認と基盤の導入（測定サブエージェント）

人間はubuntu-desktopの利用者に、パスワードなしのsudoを許可した（/etc/sudoers.d/90-claude-setup）。環境構築に必要なパッケージの導入、NVIDIAドライバの導入、再起動は、sshとsudoでAgentが行ってよい。

まず次を確認し、docs/decisions/010-compute-environment.mdに記録する。

- 「sudo -n true」が成功すること。失敗した場合は停止して人間に報告する
- OSの版、CPUのコア数、RAM、ディスクの空き容量（data/とruns/を置く場所）
- nvidia-smiの出力（ドライバの版、CUDAの版、GPUの認識）
- Secure Bootの状態（mokutil --sb-state）
- python3、git、rsync、uv、tmuxの有無と版

次に、足りないものを導入する。

- rsync、tmux、gitなど、aptで入るものはsudo aptで導入する
- nvidia-smiが動かない場合は、Ubuntuの推奨ドライバ（ubuntu-drivers）を導入し、sudo rebootで再起動する。再起動の後、sshが再び通るまで待ち（最大10分）、nvidia-smiでGPUが認識されたことを確認する
- uvはユーザー権限で導入する
- Macとの間の転送速度の目安（数百MBのファイルをrsyncで送った時間）を測る

次の場合は停止し、人間に必要な作業を報告する。

- Secure Bootが有効で、NVIDIAドライバの導入に本体の画面での操作（MOKの登録）が必要になる場合。ドライバの導入を始める前に確認し、有効なら導入せずに停止する
- 再起動の後、10分待ってもsshが通らない場合
- ディスクの空きが60GB未満の場合（Common Voice約16GB、data/processed約21GB、MUSAN、仮想環境、runs/を置くため）

sudoは環境構築に必要な操作だけに使う。システムの設定（ファイアウォール、sshの設定、利用者の追加など）は変えない。導入したパッケージと実行した管理者操作は、すべて010-compute-environment.mdに記録する。

## タスク2　cudaへの対応（実装サブエージェント）

ブランチを切って実装し、動作確認の後にmainへ取り込む。

- 学習・評価・アライメント・無発話判定のデバイスの指定を、mps・cuda・cpuのいずれでも動くようにする。設定ファイルのdeviceにcudaを書けるようにし、指定したデバイスが使えない場合は開始前に停止する（黙ってcpuに落とさない）
- cudaのときは0節の3の設定（TF32の無効化）を学習・評価の開始時に適用し、log.txtに記録する
- DataLoaderのpin_memoryなど、cuda向けの設定はcudaのときだけ有効にする
- config_snapshot.yamlとlog.txtに、実行した計算機のホスト名、デバイス名（GPUの名前を含む）、torchとCUDAの版を記録する
- results/metrics.csvの末尾に、host列とdevice列を追加する。既存の行は空欄のままとし、既存の列と値は変えない
- pyproject.tomlとuv.lockを、Linuxではcuda版のtorch、macOSでは現在のtorchが入るようにする。macOSで解決される版は変えない。uv.lockの変更で、Macの環境の版が変わらないことを確認する
- Macでpytestが全件通ること。cudaが要るテストは、cudaが無い環境では飛ばす
- 実行中のexp005に影響を与えない。exp005のプロセスが読んでいるファイル（src/以下を含む）は、学習中のプロセスには反映されないが、mainへの取り込みはexp005の実行を妨げない形で行う

## タスク3　ubuntu-desktopの環境構築と試験（測定サブエージェント）

- リポジトリをubuntu-desktopに置く。Macのリポジトリの作業ツリー（.gitを含む）を、data/・runs/・.venv/・listening/・results/error_cases/とresults/alignment_check/の音声を除いてrsyncで送る。Common Voiceは再配布が禁止されているが、自分の計算機の間のコピーはこれに当たらない。GitHubへのpushは本書では行わない
- データをrsyncで送る: data/common_voice_ja、data/musan、data/processed。送った後、ファイル数と合計サイズがMacと一致することを確認する
- uv syncを行い、torchがcudaを認識することを確認する。pytestを全件実行する
- 送り方の手順（除外するもの、送った後の確認）をscripts/sync_to_remote.shにまとめ、以後はこれを使う。runs/の結果をMacへ戻す手順もscripts/fetch_from_remote.shにまとめる。どちらもリポジトリに入れるが、ホスト名はubuntu-desktopを既定値にし、引数で変えられるようにする
- 完走確認: configs/exp000_method_b_smoke.yamlとconfigs/exp000_method_a_selection_smoke.yamlを、deviceをcudaにした設定でubuntu-desktop上で実行する。1エポックあたりの計算時間、データ待ちの時間と比率を、Macの同じ設定の値（既存のruns/の記録）と並べて、docs/decisions/010-compute-environment.mdに記録する。データ待ちの比率が0.5以上の場合は、num_workersを変えた値も測ってよい
- 完走確認の出力はubuntu-desktopのruns/に置き、fetch_from_remote.shでMacのruns/に戻す
