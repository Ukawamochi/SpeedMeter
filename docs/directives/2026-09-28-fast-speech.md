# 統括Agentへの指示（2026-09-28 高速度域への対応）

この文書はリポジトリ所有者（人間）の指示である。docs/directives/2026-09-27.mdの系統Aの途中に割り込み、高速度域への対応を最優先で行う。本書とdocs/plan.md、既存の指示書が矛盾する場合は本書を優先する。CLAUDE.mdとdocs/plan.mdの運用規則は引き続き適用する。本書をコミットしてから作業を始める。

## 背景

- ブラウザの確認用ページで検証したところ、速い発話で値が頭打ちになる。ポッドキャストを2倍速で再生しても表示があまり上がらない
- exp005のdev_window（clean）で、窓の正解の毎秒モーラ数ごとに出力の平均を集計すると、9までは概ね正しいが、10以上で過小評価が急に大きくなる。正解11台で出力10.18、12台で10.60、13台で10.86であり、出力の天井は約11である
- 学習の窓で12以上は2%足らず、14以上は0.5%未満と見積もられる（devの窓の分布に学習と同じ時間伸縮を掛けた概算）。時間伸縮は長さの倍率0.7〜1.5の一様で、速くする側は37.5%にとどまり、話速の上限は1.43倍である
- 目標: 出力の天井を現在より2〜3mora/s上げ、正解13〜14mora/sの窓まで出力が正解に追従するようにする。通常の話速域の精度は落とさない

## 0　人間の決定

1. docs/spec.mdの時間伸縮の範囲を「0.7〜1.5倍」から「0.5〜1.5倍」に広げることを許可する（0.5倍は2倍速に相当する）。これは人間による仕様変更の指示である。既定の設定（既存の実験の設定）は変えず、新しい範囲は新しい実験の設定でだけ使う
2. 高速度域の評価を新しく加える（タスク1）。これを本書の実験の主な判定に使う
3. docs/directives/2026-09-27.mdのA-3の残り（exp011）は、本書の実験の後に回す。exp010とexp012は、実行中のものを止めずに完了させる
4. ubuntu-desktopでの新しい学習では、num_workersを増やしてよい。docs/decisions/010-compute-environment.mdの4.4節で、num_workersを変えても指標がほぼ変わらないことを確認済みである。最初のエポックでデータ待ちの比率とメモリの空き（free）を確かめ、空きが2GiBを切らない範囲で決める。採用した値をconfig_snapshotとcompute.mdに記録する

## タスク1　高速度域の評価の追加（実装サブエージェントの後に測定サブエージェント）

- 評価1（正解の話速の区間別）: 既存のdev_window（clean・主指標）について、窓の正解の毎秒モーラ数を1刻みの区間（6以上7未満〜14以上）に分け、区間ごとの窓数、正解の平均、出力の平均、出力の10%点と90%点、偏りを集計する。区間の窓数が少ない場合もそのまま記録する
- 評価2（速めた音声）: devから乱数の種を固定して選んだクリップ（連続発話の組を含む）の音源を、長さ1/1.5倍（1.5倍速）と1/2倍（2倍速）に速めた音声を作り、dev_windowと同じ規則（2.0秒窓、0.25秒ずらし、按分の正解、時刻の変換）で窓を作る。窓数は各条件で数万程度とする。これをdev_fastと呼ぶ
  - 速める処理は、学習の時間伸縮とは異なる方式で行う（学習は位相ボコーダなので、評価は例えばWSOLAなど別の方式を使う）。学習と同じ処理の癖を覚えただけで評価が良く見えることを避けるためである。Pythonで使えるライブラリを探し、使った方式と版を記録する。見つからない場合は、学習と同じ方式で作り、その旨を留保として記録する
  - 評価1と同じ区間別の集計を行う
- exp005・exp007・exp010（完了後）について評価1・2を行い、results/fast_speech_eval.mdとmetrics.csvに記録する。exp005とexp007の差を、区間別の偶然の揺れの目安とする
- 判定の基準を、本書の実験の前にresults/fast_speech_eval.mdに書く。人間の目標は「正解13〜14mora/sの窓で出力が正解に追従する」ことである。これを、評価1・2の区間12以上13未満と13以上14未満での偏りと、区間の出力の平均が正解とともに単調に増えることで判定する。通常の話速域については、dev_windowのclean・主指標のMAEと、4つの帯別MAEが、exp005・exp007の範囲から011-search-plan.mdの揺れの目安s以上悪化しないことを条件とする

## タスク2　高速度域の学習（実装サブエージェントの後に測定サブエージェント、実験ごとに1つ）

基準はexp005とする。ubuntu-desktopで、exp010の完了後に次の順で学習する。Macがexp012の完了後に空けば、1つをMacで並行して学習してよい。

- exp014（伸縮の範囲を広げる）: 時間伸縮の範囲を0.5〜1.5倍、分布を対数一様にする。対数一様では速くする側（倍率1未満）が約63%になる。伸縮の確率は0.5のまま。方式Bの伸縮率の下限 max(下限, 2.0 ÷ 音源長) の規則はそのまま適用し、2倍速に近い伸縮には4秒以上の音源が要ることで、その割合がどれだけ減るかを記録する
- exp015（伸縮の範囲を広げ、速い窓を多く選ぶ）: exp014に加えて、学習の窓の選び方で、正解が10mora/s以上になる窓の出現を増やす。方法は実装サブエージェントが決め、エポックあたりの窓数は変えない。速い窓の割合を、exp005・exp014と並べて記録する

各モデルについて、既存の評価（dev_window・dev_noisy・クリップ単位・D1〜D3）とタスク1の評価1・2を行い、metrics.csvに追記する。推論時間はMacでexp005と同じセッションで測る（まとめて測ってよい）。
