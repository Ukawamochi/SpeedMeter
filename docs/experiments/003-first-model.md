## 2. 目標値に到達しているか

判定の基準は `docs/experiments/002-baseline.md` 5節の6項目である。**すべて必達**とされている。評価は dev 全件29,518件、クリップ単位。

### 2.1 必達6項目

### 2.2 総合判定

**目標未到達。** 002は6項目すべてを満たした場合のみ到達と判定すると定めており、3項目が未達である。

ただし次の3点を併記する。判定そのものは変えないが、次に取る手を決めるために必要である。

- **不足幅が小さい。** 最大でも 8以上の帯の +0.0324、全体では +0.0013（0.26%）である
- **3項目のうち2項目は統計的に目標値と区別できない。** 8以上の帯（信頼区間 1.3045–1.4603）と全体（0.4929–0.5097）はどちらも目標値をまたぐ。一方 **4以上6未満の帯（0.4012–0.4186）は区間全体が 0.40 を超えており、これは標本の揺れでは説明できない確実な未達**である
- **不足幅は学習1エポック分の改善幅より小さい。** 検証MAEの改善は直近（エポック5→6）で 0.0196 あり、まだ単調に減っている（3節）。6エポックで打ち切った学習をそのまま延ばすだけで3項目とも越える見込みが十分にある

### 2.3 002が置いた歯止めの確認

**「MAEが0.35を下回った場合、残差をモデルの不足として扱ってはならない」（002の 3.3節f）→ 該当しない。**
実測の全体MAEは 0.5013 で、0.35 の 1.43倍である。したがって現在の残差はまだモデル側の不足として扱ってよく、改善の努力を続ける意味がある。
同時に、002の指示どおり**目標値を本判定でより厳しい値に引き直すことはしない**。到達しうる下限（0.025 より大きく 0.2836 より小さい）は第6段階6-3の聴取まで不明のままである。

なお、書き起こしベースラインの 0.2836 にもラベル雑音が含まれているという002の指摘を踏まえると、モデルの 0.4946（同一部分集合）と書き起こしの 0.2836 の差 0.2110 のうち、どれだけがモデルの不足でどれだけが両者に共通のラベル雑音かは現時点で分離できない。

### 2.4 「8以上の帯を dev 全件で測り直す」条件（002の未解決点）

002は「5-4 で目標値の近傍（1.35 ± 0.15 程度）に入った場合は、dev 全件2,015件で測り直してから判定すること」と定めていた。

| 確認事項 | 結果 |
| --- | --- |
| 近傍条件に該当したか | **該当した**。実測 1.3824 は 1.35 ± 0.15（1.20 – 1.50）の内側である |
| 測り直しは必要か | **不要。今回の評価がすでに dev 全件2,015件である**（`runs/exp001/eval_dev_full.json`、`n_band_over8 = 2015`）。条件は消化済みで、判定に使う値は 1.3824 で確定する |

| 申し送り | **この帯の判定は今後も必ず dev 全件2,015件で行う。** 部分集合5,000件の値をこの帯の合否に使わない |

### 2.5 処理時間とモデルサイズ

**これらは第8段階8-3で判定する項目であり、本段階の合否には含まれない。** 以下は到達見込みの確認である。

## 3. 学習曲線から見た過学習の有無

`runs/exp001/metrics.jsonl`（6行）の全数である。検証は毎エポック dev 全件29,518件で計算されている。

| エポック | 学習損失 | 検証損失 | 学習MAE | 検証MAE | 相関 | 8以上の帯 | 最良 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | :---: |
| 1 | 526.588 | 30.931 | 1.2714 | 0.7801 | 0.8317 | 2.2673 | ● |
| 2 | 16.854 | 21.634 | 0.6032 | 0.6641 | 0.8597 | 1.9404 | ● |

| 6 | 8.096 | 12.914 | 0.4052 | **0.5013** | 0.8905 | 1.3824 | ● |

### 3.1 過学習は認められない

- **検証損失が6エポックすべてで単調減少している**（30.93 → 21.63 → 17.93 → 14.00 → 13.71 → 12.91）。反転は一度もない
- **検証MAEも単調減少している**（0.7801 → … → 0.5013）。`is_best` が全エポックで true であり、**最良エポックは最終エポック（6）である**
- 相関係数も単調に上昇している（0.8317 → 0.8905）

過学習の兆候である「学習損失は下がり続けるが検証損失が底を打って上昇する」パターンは、6エポックの範囲では一切現れていない。

### 3.2 学習は収束前に打ち切られている

**これが本判定でもっとも重要な事実である。**

- エポック数6は `configs/exp001.yaml` のコメントが明記するとおり、**所要時間の見積り（1エポック約20分＋dev全件評価約3分、6エポックで約2時間半）から決めた値**であり、収束の判定でも早期終了でもない。`log.txt` の最終行も「学習を終了した。最良エポック=6」で、設定上限に達して止まっている
- 検証MAEの改善幅は −0.1160 / −0.0549 / −0.0595 / −0.0288 / −0.0196 と縮んではいるが、**エポック6の時点でまだ 0.0196 / エポックある**。検証損失の改善幅もエポック5→6 で −0.80 と、エポック4→5 の −0.29 より大きい（単調に鈍っているわけでもない）
- 未達3項目の不足幅（+0.0013 / +0.0099 / +0.0324）は、この1エポック分の改善幅と同程度かそれ以下である

したがって**2節の「未到達」は、この構造・この設定で目標に到達できないことを意味しない。「6エポックでは到達しなかった」以上のことは言えない。**
次に取るべき手は、モデル構造や損失関数の変更ではなく、**まず同じ設定のままエポック数を増やすこと**である（7節）。

### 3.3 汎化の差は緩やかに開いている

学習MAEと検証MAEの差は、エポック2以降 0.0609 → 0.0810 → 0.0691 → 0.0891 → 0.0961 と緩やかに開いている。

この値は2つの理由で過小評価である点に注意が要る。第一に、学習MAEはエポック中の移動平均（重みが更新されながらの値）なので、**エポック終了時の重みで測れば学習MAEはこれより低く、真の差はもっと大きい**。第二に、学習と検証は話者単位で分かれているので、差には過学習だけでなく話者集合の違いも混ざる。

差が開き続けていること自体は、エポックを増やせばいずれ検証損失が反転しうることを示す。**エポックを増やす場合は検証損失の反転を監視し、反転した時点の最良チェックポイントを採る。** 反転が早すぎて目標に届かない場合は、`configs/exp001.yaml` が `augment.enabled: false` としてデータ拡張を一切使っていないため、第7段階で拡張を入れる余地がそのまま残っている。

### 3.4 その他の実行時の確認

- `runs/exp001/log.txt` 最終行付近に「MPSのCPUフォールバックは検出されなかった」とある。**CPUフォールバックの発生は無し**（CLAUDE.md の報告義務に対する確認）
- 学習率は `runs/exp001/notes.md` の短い試行（train 先頭20,000件・dev 先頭4,000件・2〜3エポック、5水準）で選ばれた 1e-4 である。3e-3 は相関が負のまま、1e-3 と 3e-4 はエポック間で検証損失が跳ね、3e-5 は進みが最も遅かった。本番6エポックでも跳ねは起きていないので、**この選択は妥当だったと確認できる**。ただし試行は最大3エポックまでしか見ておらず、**より長い学習でより大きい学習率＋減衰が有利になる可能性は否定されていない**。学習率の減衰（スケジューラ）は本設定に存在しない

## 4. 話速帯別に見た弱点

以下はすべて `runs/exp001/predictions_best.json`（dev 全件29,518件のクリップ単位予測）と `data/processed/clips.jsonl` からの再集計である。

### 4.1 弱点A: 8以上の帯（系統的な過小評価）

符号付きの誤差（予測 − 正解、mora/s）を帯ごとに見る。

- **8以上の帯のMAE 1.3824 のうち 1.2851（93%）が偏りである。** 散らばりではなく、ほぼ全件を系統的に低く見積もっている。件数比 6.8% のこの帯が全絶対誤差の 18.8% を出している
- 偏りは帯をまたいで単調に変化する（+0.114 → −0.070 → −0.301 → −1.285）。予測値を正解に回帰させると**傾き 0.8248、切片 0.7315**（予測の標準偏差 1.785 < 正解の標準偏差 1.928）で、典型的な**平均への縮み**である。交点は 4.17 mora/s 付近にあり、それより速ければ低く、遅ければ高く出る
- これは**包絡法と同じ形の弱点**である（002の 2.1節）。包絡法の原因（速い話速で音量の山が融合し、固定係数では追いつかない）とは機構が違うが、結果の形は同じで、**モデルはこの弱点を解消ではなく縮小（2.1677 → 1.3824、36%減）したにとどまる**
- 原因の候補（いずれも本タスクでは検証していない）: (i) 学習データで毎秒8モーラ以上は 4.6% しかない（`results/clip_filtering.md`）、(ii) 二乗誤差損失は雑音のある入力のもとで縮み推定を生む、(iii) 高速な発話ほどラベル（原文由来のモーラ数）と実発話のずれが大きい可能性。(iii) は第6段階6-2・6-3 の担当である

**ただしこれは代理の証拠であって、D1の代わりにはならない。** 短いクリップは「短く切り出された2.0秒窓」ではなく「もともと短い録音」であり、前後の無音の比率や録音の性質が異なりうる。005の規定どおり、**層別MAE単独を方式Bへの移行根拠にはしない**。直接測る手段はD1である（5節）。

### 4.3 弱点C: 4未満の帯は唯一の過大評価側

4未満の帯だけ偏りが正（+0.1138）で、3.0秒以上の層に限ると +0.163 とさらに大きい。002の 2.3節が包絡法について述べた事情（この帯は無音・間の占める割合が大きく、クリップ全体の毎秒モーラ数という正解値そのものが「発話していない時間」に依存する）がモデルにも当てはまる。
モデルはこの帯で目標 0.45 を 0.4033 で満たしており、現時点で最優先の問題ではない。ただし**偏りが正であること自体は、無音や間に対して出力を出しすぎている可能性を示す**。これは 005 の D2（無音窓の出力）が直接測る対象である。
