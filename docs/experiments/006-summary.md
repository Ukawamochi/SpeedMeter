## 0. 結論の要約

1. 最終モデルの候補は **exp016**。基準構成は **exp005 のまま（人間の承認待ち）**。候補の選択は dev だけで行い（docs/experiments/015）、その後に test を評価した。test の結果で候補・基準構成・設定を変えていない
2. test の値は dev と同じ向き。窓単位 clean MAE は exp005 0.4599・exp016 0.4786、雑音下まとめ MAE は 0.6816・0.7347、2倍速（x2）の天井は 11.922・13.416。dev との差は clean MAE が両モデルとも −0.016、x2 の天井は −0.019・−0.001（小さい）
3. 2節の実用上の基準: dev・test とも満たさない項目が同じ。exp005 は追従（x2 の天井 ≥ 13.0）、exp016 は雑音下まとめ MAE（≤ 0.72）と正解0の窓の雑音下（≤ 0.5）。第3段階の目標値（クリップ単位）は両モデルとも dev・test で全項目を満たす
4. ブラウザへ渡せるサイズ（ONNX fp32 2,005,372 B）だが、推論時間は exp016 も test の評価としても未測定（Mac の MPS が使えない）。信号処理・書き起こしのベースラインの test 評価、JVS、種を変えた確認、人間のブラウザでの確認は未実施
5. 推奨（根拠は 6節）: 目標の用途（倍速にした音声への追従）が主なら exp016 を最終モデルとして承認する価値がある。雑音下の誤差と無音・雑音の窓の出力を優先するなら exp005 のまま。決めるのは人間

### 5.2 特殊拍（長音・撥音・促音）の数え落とし

- **test では集計していない**（results/special_mora_analysis*.md は dev_window の clean・主指標の集計。test の窓には当てていない）。以下は dev の既存の値
- 特殊拍（ー・ン・ッ）の割合が高い窓ほど出力が小さくなる傾向が、4つの話速帯のすべてで見られる（exp005・exp016 とも）。割合 0.1 あたりの偏りの傾き（正解の話速で調整。mora/s）: exp005 −0.040・−0.106・−0.134・−0.188（4未満・4〜6・6〜8・8以上）、exp016 −0.036・−0.104・−0.143・−0.211。95%区間はどれも 0 を含まない（results/exp016_eval.md 12節）

- 損失の重みを上げた exp020 でも埋まらなかった（8以上 exp016 −0.211 → exp020 −0.214。docs/experiments/015 の結論）。原因（ラベルの読みと発話の違い、音響上の区切りの弱さなど）は未確定。音声を聴かないと確かめられない部分がある

## 6. ブラウザ実装へ渡せる状態か

### 6.1 モデルサイズ

- ONNX fp32 は 2,005,372 B（約 2.0 MB）、int8 は exp005 で 529,968 B（約 0.53 MB。exp016 の int8 は書き出していない）。パラメータ数は 498,881（exp005・exp016 とも）
- ONNX は書き出し済みで、PyTorch との出力の差の最大は exp016 で 5.7e-6 モーラ（docs/progress.md の exp016 の ONNX 書き出しの記録）。web/models.txt に exp005（必須）と exp016（試用）が入っている

### 6.2 推論時間

- **test の評価としては未測定**。exp016 の推論時間は、Mac の MPS が使えないため測っていない（exp005 と同じ構造なので、パラメータ数・計算量は同じ）
- 参考（第8段階の別測定、exp005）: PyTorch mps 中央値 1.749 ms（results/latency_010.md）、ONNX Runtime CPU fp32 中央値 1.916 ms・int8 3.765 ms（results/onnx_export.md 4節。Mac の CPU 上で、2.0秒窓1回、対数メル計算を含む）。推論間隔 0.25 秒に対して fp32 の 1.916 ms は 1.916 ÷ 250 = 0.77%。この Mac の CPU では int8 が fp32 より遅い
- ブラウザ（WebAssembly など）での推論時間は測っていない。対数メルの計算（ブラウザ側の実装）の照合は web/check.html で行うが、**人間のブラウザでの確認は未実施**
- 判断: モデルサイズの観点では渡せる大きさ。推論時間は、exp005 の別測定の値が推論間隔の 1% 未満であることから余裕があると見込まれるが、exp016 とブラウザでの値は測っていないので、渡せると断定しない

## 7. 残っている課題

1. **種が1つ**（20260921）。モデル間の差・基準との差の確かさは、揺れの目安（exp005 と exp007 の1回の観測）でしか見ていない。exp016 の別の種での学習は無い
2. **雑音下と追従の両立**。exp016 は追従を満たし、雑音下の MAE（test 0.7347 > 0.72）と正解0の窓の雑音下（test 0.5346 > 0.5）を満たさない。exp005 は逆。両方を満たす条件は dev にも test にも無い（exp017〜exp020 の条件でも見つかっていない。docs/experiments/014・015）
3. **実際の速い発話での頭打ち**: 評価1の 12 以上の区間の偏り −1.6 以下、14 以上で −5.5。倍速にした音声での追従は実際の速い発話の追従を保証しない

## 8. 基準構成の扱い

- **最終モデルの候補は exp016、基準構成は exp005 のまま（人間の承認待ち）**。docs/experiments/015 が、2節の基準を満たす条件が無い中で exp016 を候補に挙げ（x2 の天井が4条件で最も高く、満たさない項目数と超過の大きさが最小）、基準構成は exp005 のままとした。test の評価は、その後に行った。**test の結果を見て候補を選び直していない**
- 推奨と根拠: 人間が示した目標は「当面は、倍速にした音声に追従できればよい。判定の主は評価2」（docs/directives/2026-09-29.md 0節3）。この目標では、exp016 は x2 の天井が基準を満たし（test 13.416 ≥ 13.0）、x2 の MAE が exp005 より 0.8068 小さい（test 1.9830 − 2.7898）。通常の話速域（clean MAE 0.4786 ≤ 0.50）も満たす。一方、雑音下の MAE は exp005 より 0.0531 悪く（0.7347 − 0.6816）基準を満たさず、無音・雑音の窓の出力（雑音下 0.5346）も基準を満たさない。**雑音のある環境での使用を主にするなら exp005 の方が基準を満たす項目が多い**（exp005 は満たさない項目が追従の1つだけ）。どちらを最終モデルにするかは、用途の重みづけによる人間の判断で、本書では決めない
- 基準構成を exp016 に変える場合に必要な手続き: 人間の承認、Mac での exp016 の推論時間の測定（exp005 と同じセッション）、web/ での確認
