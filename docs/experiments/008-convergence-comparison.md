## 6. 注意点の確認

### 6.1 exp004 は停止規則の意味で収束していない可能性がある

- exp004 は早期終了ではなく上限30エポックで終了した（最良27、終了時点で改善なし3エポック。patience 5 に達していない）。exp003 は早期終了（最良25、終了エポック30が上限と偶然一致）
- exp004 の dev MAE はエポック27（0.4383）以降 0.4485・0.4432・0.4436 で、改善は止まりかけているが停止規則は満たしていない。したがって exp004 の値は「停止規則上の収束点」の値ではなく、延長すればさらに下がる余地が否定できない
- 基準構成の選択への影響: 延長の余地があるのは exp004 側なので、この非対称は exp004 に**不利**な方向にしか働かない。exp004 を選ぶ結論を覆す要因にはならないが、exp004 の数値を最終値として扱ってはならない

### 6.2 雑音ファイルが学習と評価で重なっている（確認済み）

コードから確認した事実:

- dev_noisy（`configs/eval/dev_noisy.yaml`: `musan_root: data/musan`、`musan_subsets: [noise]`）は `src/spkrate/eval/noisy.py` の `make_noise_source` で `MusanNoiseSource(data/musan, subsets=("noise",))` を作る
- exp004 の拡張（`configs/exp004.yaml` の `augment.musan_root: data/musan`）は `src/spkrate/train/train.py` で `MusanNoiseSource(config.augment.musan_root)` を作り、サブセットは既定の `("noise",)`
- 無音サンプル（`src/spkrate/train/silence.py`）も `MusanNoiseSource(settings.musan_root)`（`data/musan`、既定 `noise`）。**exp003 もこの経路で MUSAN noise を学習に使っている**（`config_snapshot.yaml` の `silence_counts.musan_noise` は両者とも 2,361件/エポック）
- D2 の雑音窓（`scripts/window_diagnostics.py`、`MUSAN_ROOT = "data/musan"`）も同じ
- `MusanNoiseSource.paths` は `data/musan/noise` 以下の wav 全件（930ファイル）を `sorted(rglob("*.wav"))` で列挙するだけで、学習用と評価用にファイルを分ける仕組みはどこにも無い
- したがって **dev_noisy・D2 の雑音ファイルは、exp004 の拡張（発話への重畳）と、exp003・exp004 の無音サンプル（正解0の雑音のみ）の両方と同じ930ファイルの集合から取られている**。切り出し位置は乱数で異なるが、ファイル（雑音の種類）は重なっている
- 残響: dev_noisy は固定の部屋（6.0×4.5×2.7 m、RT60 0.5秒、反射次数30）の1本。exp004 の拡張は部屋 3〜10 × 3〜10 × 2.3〜4.0 m、RT60 0.1〜0.7秒、反射次数12 の無作為な部屋で、dev_noisy の部屋の寸法と RT60 は学習時の範囲に含まれる。SNR 5/10/15dB も学習時の範囲 0〜20dB に含まれる

影響:

- dev_noisy の値は「学習時に見た雑音の種類・残響・SNR の範囲内」での頑健性であり、未知の雑音に対する頑健性を測っていない。exp004 の noisy 指標（MAE 0.5956）は未知の雑音に対する値より良く出ている可能性がある（どの程度かは本資料からは言えない）
- ただし重なりは exp004 だけの利点ではない。exp003 も同じ930ファイルを「正解0の雑音」として毎エポック見ている。exp003 の noisy での崩れ（5節の過小方向の偏り）は、雑音ファイルが未知だったことでは説明できない
- 両者の noisy MAE の差（2.5053 vs 0.5956、約4.2倍）と、1.0未満の件数の差（17,605 vs 562）は大きく、重なりによる有利さでこの順序が逆転するとは考えにくい。ただし未知の雑音での値は測っていないので、この点は推測である

### 6.3 経路とコミットの違い

- 両者の設計上の違いは拡張の有無だけだが、学習データの経路が異なる: exp003 は features 経路（事前計算した float16 の対数メル）、exp004 は waveform 経路（波形から都度計算）。exp001/exp002 と同じ組み合わせである
- 学習時のコミットは exp003 `320580a`、exp004 `f38cc9f`。`git diff 320580a f38cc9f -- src` の差は `src/spkrate/train/train.py` の28行の追加のみで、内容はエポックごとの個別チェックポイント保存（`train.save_every_epoch`）とその説明。学習の計算は同一である

### 6.4 再開元の違い

- 両者とも exp001/exp002 のエポック6の `checkpoint_last.pt`（モデルと最適化器の状態）から再開し、エポック7〜30 の24エポックを学習した
- 再開時点の dev MAE は exp003 側 0.5013、exp004 側 0.5992 で、exp004 は 0.098 悪い位置から始まっている。clean の比較はこの点で exp004 に不利である（それでも最終の clean MAE の差は 0.0037）

## 7. 結論: 以後の基準構成は exp004（無音サンプルあり・拡張あり）とする

**判断（判断サブエージェントの結論。統括・人間の承認対象）: `configs/exp004.yaml`（`009-exp004-silence-aug`）を以後の基準構成とする。**

理由（優先順）:

1. **noisy の指標で exp004 が大きく上回る。** dev_noisy 3条件まとめの MAE 0.5956 vs 2.5053、相関 0.8643 vs 0.3896。4つの帯すべて・3つの SNR すべてで exp004 が良い。
   exp004 は SNR 5dB でも clean から +0.19 の悪化にとどまるが、exp003 は SNR 15dB でも MAE 2.05 で、雑音下では推定器として機能していない
2. **雑音下の低出力（< 1.0 mora/s）が exp004 ではほぼ生じない。** 3条件合計で 562件（0.6%）vs 17,605件（19.9%）。exp003 は雑音下で系統的に過小に出す（SNR 5dB で偏り −2.94、過大に出したのは 4.8%）
3. **無音での出力は exp003 の方が良いが、exp004 も閾値内に入った。** デジタル無音 0.0043 vs 0.5227 モーラ / 2.0秒、MUSAN noise 0.1020 vs 0.7681。exp003 は「無音は0モーラ」をほぼ満たし、exp004 は満たしていない（毎秒 0.26 モーラ相当を出す）。
   一方で exp004 は B2（1.0）を無音・雑音とも下回り、exp002（1.44・1.74）からは大きく改善した。
   無音での出力の差（0.5 モーラ / 2.0秒）と雑音下の発話での誤差の差（MAE で約1.9 mora/s、低出力の件数で約17,000件）を比べると、後者の方が実用上の影響が大きいと判断した。
   雑音下で話速がほぼ0に落ちる挙動は、無音で小さな正の値を出す挙動より、話速計として致命的だからである
4. clean の指標はほぼ同等（MAE 差 0.0037 はエポック間の揺れより小さい。帯別は 4未満のみ exp003 が良く、他の3帯と相関は exp004 が良い）。clean で順位を決める根拠はない
5. 推論時間（同一セッションの中央値差 0.007 ms）・モデルサイズ（差 64 バイト）に実質的な差はない

この結論に付く留保:

- exp004 は上限で終了しており収束していない可能性がある（6.1節）。数値は最終値ではない。この非対称は exp004 に不利な方向にのみ働く
- noisy 指標は学習時と同じ MUSAN noise の930ファイル・学習範囲内の残響と SNR での値で、exp004 に有利に偏りうる（6.2節）。未知の雑音での頑健性は未測定。ただし exp003 も同じ雑音ファイルを学習で見ており、順序の逆転は考えにくい
