## 6. 結論: 以後の基準構成は exp005（方式B）とする

**判断（判断サブエージェントの結論。統括・人間の承認対象）: `configs/exp005.yaml`（`010-exp005-method-b`・`010-window-eval-exp005`、方式B、学習用の一覧で絞った学習クリップ、MUSAN noise の学習用分割、無音サンプルと拡張は exp004 と同じ）を以後の基準構成とする。**

理由（優先順）:

1. **窓単位の必達目標（spec.md「窓単位の目標値」）をすべて満たすのは exp005 だけである。** clean・主指標の MAE で 4未満 0.2893・4以上6未満 0.4572・6以上8未満 0.4692・8以上 0.6810・全体 0.4755（目標 0.70・0.60・0.60・0.90・0.70）。exp004 と exp006 は 4未満 以外を満たさない
2. **雑音下の窓単位で大きく上回る。** 雑音下まとめの MAE 0.7001（exp006 1.3869、exp004 1.3476）、偏り −0.0154（−1.1711、−1.1304）。3つの SNR と4つの帯のすべてで最良。008 で人間の指示により優先した「noisy の指標」について、推論時の単位（窓）で最良である。exp005 は評価用の雑音を学習で見ていないので、この値は exp004 より条件が厳しい
3. **窓の端の不整合と無音への出力が解消に近づいた。** D1 0.1009（B1 の閾値 0.25 未満）、正解0の窓の出力平均 0.1738 モーラ（中央値 0.047）、D2 デジタル無音 0.0306。009 で方式Bへ移行する理由とした B1 の問題は、方式Bで閾値未満になった
4. **8以上の帯の過小が大きく減った。** 窓単位の偏り −0.3655（exp006 −0.9775、exp004 −1.2552）。このツールの目的とされる速い発話の検出（docs/questions.md 2026-09-26 回答の3）に直接効く
5. clean のクリップ単位でも最良（dev 0.4170）で、方式Bによってクリップ単位の clean が悪くなってはいない
6. 推論時間（中央値 1.7493 ms、差は最大 0.0102 ms）とモデルサイズに実質的な差は無い

改善が方式Bによるものであることは、学習データと雑音をそろえた対照 exp006 との差（3.2節）で確かめた。exp004 からの窓単位の clean の改善 −0.3559 のうち −0.2713 が方式Bの差で、計算機・中断・乱数の差（5節の留保1・2）で説明できる大きさを大きく超える。

この結論に付く留保:

- exp005 は mps、比較の対照 exp006 は cuda で学習・評価した。同じ計算機での対照ではない（5節の留保1）
- **クリップ単位の雑音下は exp005 が exp006 より +0.0054 悪く**、遅い2帯で +0.0325・+0.0585 悪い。exp005 は雑音下で遅い発話をやや過大に出す（クリップ単位の偏り +0.05〜+0.07、窓単位の遅い帯の偏り +0.21〜+0.28）。窓単位の雑音下の遅い帯の MAE は exp005 の方が良いので結論は変えないが、基準構成に採ることでこの傾向を引き継ぐ
- 正解0の窓と雑音への出力の裾は残る（99%点 3.127、D2 MUSAN noise の最大 11.2277）
- 8以上の帯の過小（−0.3655、雑音下 −0.5970）は残り、平均への回帰と整合する形である（4.1節、推測）
- 3モデルとも上限30エポックで終了しており、値は最終値ではない（5節の留保8）
- 方式Bのクリップ単位の値の出し方と D1 の雑音下の定義は spec.md に定めが無い（5節の留保4・5、7節）
- 第7段階7-1（残りの条件の探索計画）には進まない。探索する条件の提案は書かない

## 7. 人間の承認が必要な事項

1. **本文書の結論の承認**: 以後の基準構成を exp005（`configs/exp005.yaml`、方式B）とすること。根拠は、窓単位の必達目標をすべて満たす唯一のモデルであること、雑音下の窓単位・D1・正解0の窓の出力・8以上の帯の偏りで大きく改善したこと（6節）。exp005 は mps、対照の exp006 は cuda で学習・評価しており、同じ計算機での対照ではない点を含めて承認を求める
2. **方式Bのクリップ単位の値の出し方の確認**（questions.md 2026-09-27 の確認事項1）: クリップ全体を1回で入力し、出力の総和をクリップ長で割る既存の手順を方式Bにも当てはめてよいか。あわせて、方式Bを基準構成とした後、クリップ単位の dev・dev_noisy を引き続き比較の指標として記録するか（推論は2.0秒窓で行うので、本文書では窓単位を主に、クリップ単位を参考として扱った）
