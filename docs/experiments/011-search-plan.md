010 4.1節は、8以上の帯だけが負に残り他の帯が小さな正になる形を「平均への回帰（8以上の学習データの少なさ）と整合する」と推測している。003 5.2節は8以上の過小への手当てとして「損失関数（ポアソン）・拡張（時間伸縮）の比較」を挙げている。これに沿って、次の3条件を精度の目的に置く。

- **exp008 損失をポアソンに**（plan.md の探索対象「損失関数」。spec の「損失: 二乗誤差とポアソン損失を比較する」がまだ行われていない）。ポアソン損失（`PoissonNLLLoss(log_input=False)`、損失 = 出力 − 正解 × log 出力）は、正解0の窓で損失が出力そのものになり、小さな正の出力にも一定の勾配がかかる。二乗誤差は0付近の勾配が小さい。一方、正解が大きい窓の誤差への重みは相対的に下がる（勾配 = 1 − 正解/出力）ので、8以上の帯には悪く効く可能性もある。向きの事前の見込みは持たず、両方の現象を測る
- **exp010 時間伸縮の伸縮率を対数一様に**（探索対象「データ拡張の強度」）。現在の伸縮率 s（長さの倍率）は [0.7, 1.5] の一様分布で、伸縮した窓のうち速くなる（s < 1）ものは 37.5%、対数の平均は +0.072（平均で約7%遅くする向き）である（`method_b.py` の抽選。伸縮の確率は0.5）。対数一様にすると s < 1 が 46.8%、対数の平均は +0.024 になり、学習の正解の分布が速い側へ少し広がる。範囲 0.7〜1.5（spec「データ拡張」）と確率は変えない。8以上の帯の学習データを増やすことで平均への回帰を弱められるかを確かめる
- **exp011 膨張率を2倍に**（探索対象「膨張率」）。受容野を 69 フレーム（0.69秒）から 131 フレーム（1.31秒）に広げる。パラメータ数と計算量は変わらない。正解0の窓の大きな出力（雑音の一部を発話と取り違えた出力と考えられる）が、長い文脈を見ることで減るか、また速い発話の話速を長い範囲から推定できることで8以上の過小が減るかを確かめる（どちらも推測）

受容野 131 フレームは 005 の推奨（51〜101 フレーム）を超えるが、上限 201 フレーム（`CnnConfig` が拒否する値）は下回る。推奨は方式A（クリップ全体で学習）で窓の端の取りこぼしを小さく保つための値で（005 2.4節）、方式Bでは窓の端を学習で見ている。端への影響は D1 で監視する（2.2節の守り G5）。spec に受容野の定めは無い。

- 積和の回数は、畳み込みごとに「入力チャネル × 出力チャネル × カーネルの要素数 × 出力の要素数」を足した値（偏りの加算・活性化・正規化は含まない）。周波数段は 80 → 40 → 20 → 10 の各段で時間 201 フレーム。**exp005 では周波数段の2層目と3層目（各 74.1 百万）で全体の 62% を占める**。時間段の1層目（入力 640 = 64 チャネル × 周波数 10）が 49.4 百万、残りの時間段4層が各 9.9 百万
- 0.25秒ごとに推論するので、exp005 は常時動かすと毎秒約 958 百万回の積和になる
- fp32 の大きさの見込みは パラメータ数 × 4 バイト + 約 10 KB（exp005 の ONNX の実測との差）。int8 は exp005 で 529,968 B（パラメータあたり約 1.06 B）
- 軽さの条件は、計算量を大きく減らす周波数段のチャネル数（exp009）と、パラメータ数を大きく減らす時間段のチャネル数（exp012）の2つを、それぞれ1要素の変更として置く。exp013 は exp009 と同じ要素（周波数段のチャネル数）をさらに半分にするもので、exp009 が精度を保ったときだけ、どこまで減らせるかを確かめるために行う
- 「層数」の削減は、この構造では効果が小さいか（時間段を1層減らしても積和 −4%）、他の要素を同時に変えることになる（周波数段を1層減らすと時間段の入力が倍になるか、刻みを変えて入力の一部を捨てる）ので、本計画では行わない

## 2. 差の読み方と採否の基準（事前に固定する）

### 2.1 揺れの目安 s

揺れの記録（results/run_variance.md 3節）は、exp005（mps、種 20260921）と exp007（cuda、種 20260929）の2回の学習の差である。これには種の差と学習の計算機の差が混ざり、推論の計算機の差は無視できる（1節で 1e-6 の大きさ）。**差は指標ごとに1つしかなく、学習ごとの標準偏差の推定の95%信頼区間は観測値の 0.45倍〜32倍と粗い**（同 3節の留意点）。

粗さへの対処として、本計画では次の3つを行う。

1. **下限と共通化**: 観測された差 d がたまたま小さかったと考えられる指標には下限を置き、関連する指標（帯どうし、clean と雑音下）では大きい方の値を共通に使う。全体の MAE の d（clean 0.003、雑音下 0.0006）は、最良エポックの検証 MAE の差 0.004、エポック21〜30の検証 MAE の標準偏差 0.007〜0.010 より小さいので、下限を 0.005 とする
2. **2つの基準との比較**: 条件の値を exp005 と exp007 の**両方**と比べ、2つの値の範囲（基準の範囲）の外へ s 以上出たときだけ差とみなす。基準の範囲の中点からは d/2 + s ≥ 1.5d 離れることになる。学習ごとの標準偏差を d/√2 と見積もると、条件の値と中点の差の標準偏差は約 0.87d なので、その約1.7倍以上に当たる
3. **目的の指標群での一致**: 採否は、条件ごとに事前に決めた「目的の指標群」（2.2節）で、同じ向きの差が複数の指標にそろって出ることを求める。1つの指標だけが s を超えても採らない。6条件 × 多数の指標を見るので、偶然に1つが超える可能性は高い

判定の言葉:

- **改善**: 条件の値が、基準の範囲の良い方の端より s 以上良い（MAE・99%点・割合・D は小さい方が良い、偏りは絶対値が小さい方が良い）
- **悪化**: 基準の範囲の悪い方の端より s 以上悪い
- **差なし**: それ以外。A-4 ではこれを「効果なし」と扱う（指示書 A-4）

計算機の違いの読み方: ubuntu で学習する条件（種 20260921）は、exp005 との差に計算機の差が、exp007 との差に種の差が混ざる。mac で学習する exp009（種 20260921）は、exp005 との差が条件の違い（と mps の非決定的な演算）だけになる。上の判定は2つの基準の両方に対して差を求めるので、どちらの計算機で学習した条件にも同じ規則を使う。報告では「同じ計算機の基準との差」（ubuntu の条件は exp007、mac の条件は exp005）も併記する。

判定が境目にあるとき（改善・悪化の判定が s の 1〜1.5倍の間の差で決まるとき）は、A-4 でその旨を書き、「効果なし」として扱う。同じ条件を別の種で学習し直すことは本計画の6条件に含めない（必要なら A-4 で人間の判断を求める）。

| G6 | 8未満の3帯の偏り（clean）が悪化しない | 4未満 ≤ +0.1154、4以上6未満 ≤ +0.1541、6以上8未満 ≤ +0.1041（絶対値で） |

G6 は、8以上の過小を減らす代わりに遅い帯の過大（平均への回帰の反対側）が増えることを検出するために置く。

**目的の指標群（どちらか一方が改善し、他方が悪化しないこと）**

| 群 | 改善の条件（両方を満たす） | 悪化の条件（どちらかに当たる） |
| --- | --- | --- |
| P8: 8以上の過小 | clean の8以上の偏りの絶対値 ≤ 0.3011 − 0.064 = **0.237**、かつ雑音下まとめの8以上の偏りの絶対値 ≤ 0.5970 − 0.064 = **0.533** | clean の絶対値 > 0.4295、または雑音下の絶対値 > 0.675 |
| P0: 正解0の窓の裾 | 雑音下まとめの正解0の窓の 99%点 ≤ 6.361 − 0.9 = **5.46**、かつ平均 ≤ 0.4064 − 0.07 = **0.336**（または clean で 99%点 ≤ **2.53** かつ平均 ≤ **0.144**） | 雑音下まとめの平均 > 0.549、または 99%点 > 8.15、または clean の平均 > 0.233 |

- 採る: 守りをすべて満たし、P8 か P0 の少なくとも一方が「改善」、もう一方が「悪化」でない
- 採らない: それ以外（「差なし」は A-4 で「効果なし」）
- 記録するが採否に使わない値: 雑音下の帯別 MAE と SNR 別の値、クリップ単位の dev・dev_noisy（指示書 0節の2により補助の指標）、D1 の雑音下、D2、D3、全窓の値、エポック21〜30 の検証 MAE の平均。これらが s を超えて悪化した場合は A-4 で留保として書く

条件ごとの補足:

- **exp008（ポアソン）**: 損失の大きさと勾配の大きさが二乗誤差と違うので、学習率 1e-4・勾配の上限 5.0・30エポックのままでは実質の学習の速さが変わる。これは損失を変えることに伴う差として受け入れ、学習率は変えない（1要素の変更）。最良エポックが 30 で、エポック26〜30 の検証 MAE がまだ単調に下がっている場合は「未収束」と記録し、A-4 は結論に留保を付ける（延長は本計画に含めない）。検証の指標（`mae_moras_per_sec`）と最良エポックの選び方は exp005 と同じ
- **exp010（対数一様）**: 目的は P8。学習の前に、エポック1の窓の正解（アライメントと伸縮率だけで計算でき、音声は要らない）のうち 16 モーラ（毎秒8）以上の割合を、一様と対数一様で比べて記録する（4.2節）。割合がほとんど増えない場合も学習は行うが、A-4 の読み方に使う
- **exp011（膨張率2倍）**: 目的は P0 と P8 の両方。D1（G5）で窓の端への影響を監視する。受容野は log.txt と config_snapshot.yaml に記録される

### 2.3 軽さの条件（exp009・exp012・exp013）の採用の基準

「精度を保つ」の判定（すべて満たすこと）:

| # | 項目 | 許す悪化の上限（基準の範囲の悪い方の端から） | 基準 | 理由 |
| --- | --- | --- | --- | --- |
| L1 | 窓単位の必達目標（clean・主指標の5項目） | — | G1 と同じ | spec の必達 |
| L2 | clean MAE 全体 | +0.010（2s） | ≤ 0.4886 | 基準の約2%。エポック間の検証 MAE の揺れ（隣り合うエポックの差 0.011〜0.012）と同程度で、これより小さい悪化は区別できない |
| L3 | 雑音下まとめ MAE 全体 | +0.015（3s） | ≤ 0.7151 | 基準の約2% |
| L4 | clean の帯別 MAE | +0.022（2s） | 4未満 ≤ 0.3194、4以上6未満 ≤ 0.4834、6以上8未満 ≤ 0.5017、8以上 ≤ 0.7030 | 帯ごとの揺れの2倍 |
| L5 | 8以上の偏り（精度の目的を後退させない） | s | clean の絶対値 ≤ 0.4295、雑音下まとめの絶対値 ≤ 0.675 | P8 の悪化の条件と同じ |
| L6 | 正解0の窓の出力（精度の目的を後退させない） | s | clean の平均 ≤ 0.233、雑音下まとめの平均 ≤ 0.549、雑音下まとめの99%点 ≤ 8.15 | P0 の悪化の条件と同じ |

軽さの効果の判定:

- パラメータ数・積和の回数・ONNX のファイルの大きさ（fp32・int8）は設定で決まる（1.2節の見込み）。実測の値を記録する
- 推論時間: ONNX Runtime の CPU（fp32、1スレッドと既定のスレッド数）と PyTorch の mps で、exp005 と同じセッションで交互に測る（5節）。**ONNX fp32・1スレッドの中央値が exp005 より 10% 以上短い**ことを軽さの効果の条件とする。ブラウザの WebAssembly の実行は1スレッドに近いと考え、1スレッドの値を主にする（推測）。10% は、同じ構造の3モデルを同じセッションで測った中央値の差が 0.6%（results/latency_010.md）だったことに対して十分大きい差として置く
- 採る: 「精度を保つ」をすべて満たし、推論時間の条件を満たす。採った軽さの条件が複数あるときは、A-4 で精度と推論時間・大きさの関係から選ぶ（指示書 A-4）。軽さの条件は、精度が改善しても精度の条件としては扱わない（改善は記録する）

| 構成 | 積和の比 | ONNX fp32 1スレッド（対数メルを含む） | ONNX fp32 既定のスレッド数 | PyTorch mps |
| --- | ---: | ---: | ---: | --- |
| exp005 | 1.00 | 実測 2.83 ms | 実測 1.92 ms | 実測 1.75 ms |
| exp009 | 0.43 | 約 1.3 ms | 約 0.8 ms | ほぼ変わらない見込み（呼び出しの固定の時間が大半と考える。推測） |

int8 は Mac の CPU では fp32 より遅かった（results/onnx_export.md 4節）ので、推論時間の条件は fp32 で判定し、int8 は記録だけにする。int8 の dev_window の評価は A-4 の承認後の系統Bの書き出し直しで行う（指示書 系統B）。

## 4. コードの変更（A-3 の担当が実装する）

設定の変更とコードの変更は別のコミットにする（CLAUDE.md）。コードの変更は main に入れてから（テストを通してから）その条件のブランチを切る。

### 4.1 計算量の記録（軽さの条件で必要。全条件で使う）

- `src/spkrate/models/cnn.py` に、設定と入力フレーム数（既定 201）から積和の回数を数える関数（例: `estimate_macs(config, num_frames=201)`）を加え、`model_summary` に含める（`config_snapshot.yaml` に残る）。数え方は1.2節の注記のとおり（畳み込みごとに 入力チャネル × 出力チャネル × カーネルの要素数 × 出力の要素数、出力層を含む）
- テスト: cnn_base で 239.5 百万（1.2節の値）、1.2節の表の各構成で表の値になること
- 記録の場所: metrics.csv の列に積和の回数が無い場合は列を増やさず、各条件の results の文書と A-4 の表に書く（列を足すかは A-3 の担当が既存の列を見て決める）

### 4.2 時間伸縮の伸縮率の分布（exp010）

- `AugmentConfig`（`src/spkrate/data/augment.py`）に `time_stretch_distribution: str = "uniform"` を加える。取りうる値は `uniform`・`log_uniform`。それ以外は設定の読み込みで止める
- 方式Bの抽選（`src/spkrate/train/method_b.py` の `rng.uniform(low, high)` の行）で、`log_uniform` なら `exp(rng.uniform(log(low), log(high)))` を使う。下限 `low = max(0.7, 2.0 ÷ 音源長)` の決め方は変えない。**乱数の消費の回数を一様のときと同じにする**（他の拡張の乱数の系列をずらさないため）
- 方式Aの経路（`augment.py` の時間伸縮の抽選）にも同じ分岐を入れるか、方式Aで `log_uniform` を指定したら止める（どちらにするかは A-3 の担当が決め、docstring に書く）
- テスト: 既定値（`uniform`）で exp005 の設定の抽選の結果が変更前と同じになること（同じ種で同じ伸縮率の列）。`log_uniform` の伸縮率が [low, high] に収まり、多数回の中央値が √(low × high) に近いこと
- 学習の前の確認（学習とは別に、音声を読まずに行う）: exp005 と exp010 の設定で、エポック1の学習窓の正解（アライメント・伸縮率・窓の位置から `window_mora` で計算）の分布を求め、16 モーラ以上の割合と4帯の割合を記録する。記録先は exp010 の結果の文書
- spec は変えない（spec「データ拡張」は範囲 0.7〜1.5 を定めるが分布を定めていない。範囲は変えない）

### 4.3 その他

- exp008 のポアソン損失は `train.loss: poisson` で既に選べる（`src/spkrate/train/train.py`、`PoissonNLLLoss(log_input=False, eps=1e-8)`）。これまで完走確認（exp000_smoke）でしか使っていないので、本番の前に ubuntu で短い完走確認（`max_train_clips` を小さくした1エポック）を行い、損失が有限であることを確かめる
- exp011・exp012・exp013・exp009 はモデルの設定だけの変更で、`CnnConfig` の検査（受容野 201 以下など）を通る。ONNX への書き出し（`python -m spkrate.export.to_onnx`）がチェックポイントのモデル設定を読んで書き出せることを、最初の軽さの条件で確かめる（書き出せなければそこで修正する）
- 推論時間の測定（`scripts/measure_latency.py`）は、PyTorch と ONNX を同じセッションに混ぜると ONNX Runtime のスレッドの影響で PyTorch が遅くなった（results/onnx_export.md 4節）。したがって5節のとおり2つのセッションに分ける。コードの変更は要らない見込み

## 7. A-4 への引き継ぎ

- A-4（`docs/experiments/012-final-config.md`）は、2節の基準で各条件を「採る」「効果なし」「悪化」に分け、精度とモデルの大きさ・推論時間の関係を表にする
- 採った精度の条件と採った軽さの条件が両方あるとき、それらを組み合わせた構成は本計画で学習していない（1回に変える要素は1つ）。組み合わせを基準構成にするには組み合わせの学習と確認が要るので、A-4 で人間の承認を求める事項として書く
- 2.1節の揺れの目安は2回の学習からの粗い値である。A-4 の結論が境目の差（s の 1〜1.5倍）に依存する場合は、その条件を種を変えて学習し直すかを人間の承認事項として書く
