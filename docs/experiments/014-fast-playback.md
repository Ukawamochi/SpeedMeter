### 2.2 単独の効果と、足し合わされなかったこと

- **選び直し 3 → 1 の単独（exp016）**: 追従はほぼ保たれた（x2 の天井 −0.070、評価2の出力の平均は全区間で −0.08 以内。3.3節）。雑音下まとめ MAE −0.0241、正解0の窓の雑音下まとめ −0.1342、雑音下まとめの偏り −0.0961。学習の毎秒10以上の窓を 18.77% → 14.63% に減らしても評価2の追従はほとんど落ちず、雑音下は良くなった
- **無音 0.06 の単独（exp017）**: 正解0の窓の雑音下まとめ −0.1604（0.4860 で基準を満たす）、雑音下まとめ MAE −0.0197、D2 MUSAN noise −0.2638。一方で評価2の出力が全区間で下がり（x2 で −0.17〜−0.67）、天井は −0.668 下がって 12.819 と追従の基準を外れた。clean の偏りも −0.0442 と負に大きくなった
- **組み合わせ（exp018）では、2つの単独の効果は足し合わされなかった。**

  - 雑音下まとめ MAE: 単独の和は −0.0437 だが、組み合わせは −0.0047 にとどまり、exp016 より +0.0193、exp017 より +0.0150 悪い。SNR 別も同じ向き（exp018 − exp016 は 5 / 10 / 15dB で +0.0155 / +0.0210 / +0.0214）

### 2.3 解釈（推測）

以下は推測であり、本書の測定で確かめたものではない。

1. **雑音下まとめ MAE の違いは、主に雑音下での出力の全体の高さ（過大）の違いである（観察）。** 7モデルを雑音下まとめの偏りの小さい順に並べると、exp007 −0.0206、exp005 −0.0154、exp014 +0.0139、exp016 +0.0509、exp017 +0.1062、exp018 +0.1324、exp015 +0.1470 で、雑音下まとめ MAE も同じ順に 0.6995、0.7001、0.7113、0.7490、0.7533、0.7683、0.7730 と大きくなる（順位が一致する。results/exp018_eval.md 3節の値）。雑音下の悪化は、8未満の3帯の過大（exp018 +0.324 / +0.409 / +0.285、基準 +0.13〜+0.28）に表れている。013 5.3節の4の推測（強く縮めた窓が増え、雑音の時間変化を速さと取り違える）と整合する
2. **足し合わされなかった理由として、出力の全体の高さが学習ごとに動くことが考えられる（主な推測）。** exp018 は学習の窓が exp016 と同じで、無音サンプルだけが違う。それでも clean の偏りは exp016 −0.0384 → exp018 +0.0187（差 0.057）、雑音下まとめの偏りは +0.0509 → +0.1324 と、全体が高い側へ動いた。同じ設定の学習し直しで clean の偏りは 0.022、正解0の窓の雑音下まとめは 0.072 動く（results/run_variance.md 3節）。無音サンプルを増やすと出力を低くする向きに働く、という読み（exp017）と、exp018 で全体が高くなったことは矛盾する。2つの変更の効果（雑音下まとめ MAE で 0.02 前後、正解0の窓で 0.13〜0.16）は、この「出力の高さの学習ごとの揺れ」を通じて表れる大きさと同程度か、それより小さい可能性がある。1回ずつの学習では、効果と揺れを分けられない
3. **ただし、揺れだけでは説明しきれない差もある。** exp017 の x2 の天井の低下（−0.668）は、exp005 と exp007 の x2 の天井の差（0.069）の約10倍である。exp005・exp007 は伸縮 0.7〜1.5 の学習で、伸縮 0.5〜1.5 と選び直しを使う学習の揺れは測っていない。伸縮を広げた学習では評価2の出力の高さの揺れが大きい可能性があるが、確かめていない
4. **選び直しの回数と雑音下の精度の間には、トレードオフが見える（観察と推測）。** 無音 0.03 の3条件で、選び直し 0 → 1 → 3（exp014 → exp016 → exp015）に対し、x2 の天井は 12.587 → 13.417 → 13.487、雑音下まとめ MAE は 0.7113 → 0.7490 → 0.7730。0回と1回の間を直線で内挿すると、天井 13.0 のときの雑音下まとめ MAE は約 0.730 で、0.72 を超える（写した値からの粗い計算で、内挿の妥当性は確かめていない）。選び直しの量を調整するだけでは2節の基準を両方満たすのは難しい可能性がある
5. exp018 の P0 の99%点と D2 MUSAN noise が exp016・exp017 のどちらより小さいことは、2つの変更が裾（強く過大に出る少数の窓）には足し合わされる向きに効いたことを示すのかもしれないが、平均には表れていない

### 5.2 1節で人間が問題視した現象との関係

1節の現象は、確認用ページで長い単語を使って話すと毎秒モーラ数が期待するほど上がらない、というものである。

1. **現象の一部は特殊拍の数え落としで説明できる。** 長い単語は特殊拍を多く含みやすく、特殊拍の割合が 0.2 増えると 8以上の帯で約 0.38〜0.44 mora/s 出力が下がる。1節の推測（音響上の区切りを数えるように振る舞い、区切りの弱いモーラを数え落とす）と矛盾しない（相関の分析で、文体・話者などの交絡は切り分けていない）
2. **ただし大きさは、倍速再生で見られる過小や高い話速での頭打ちより小さい。** 評価2 x2 の全体の偏りは exp005 −2.786、exp016 −1.860 で、評価1 の 13to14 の偏りは −2.286〜−2.403 ある。長い単語で速く話したときに上がらない主な原因が特殊拍か、高い話速での頭打ちかは、この分析だけでは切り分けられない（推測。results/special_mora_analysis.md 1節と同じ）
3. **本書の変更は、特殊拍の数え落としには効いていない。** 時間伸縮・選び直しは窓全体を一様に縮めるので、窓の中の特殊拍の割合も、特殊拍の音響上の区切りの弱さも変えない。無音サンプルの追加もこれに関係しない。したがって、exp016 などを使っても、1節の現象のうち特殊拍による分（割合0.1あたり 0.2 mora/s 前後）は残ると考える（推測）
4. 評価2（倍速の音声）での特殊拍の効果は集計していない。倍速にすると特殊拍（特に長音の延長や促音の閉鎖）が短くなり、効果が変わる可能性がある（推測）

## 7. 結論: 以後の基準構成は exp005 のままとする

**判断（判断サブエージェントの結論。統括・人間の承認対象）: 指示書2節の実用上の基準をすべて満たす条件は無い。以後の基準構成は exp005（`configs/exp005.yaml`）のままとし、exp015・exp016・exp017・exp018 は採用候補としない。基準の上では、ブラウザの確認用ページ（web/）で使うモデルに加えるものは無い。**

理由（優先順）:

1. **exp015〜exp018 はどれも雑音下の基準（雑音下まとめ MAE ≤ 0.72）を満たさない**（0.7490〜0.7730）。不足は最も小さい exp016 でも +0.0290 で、学習ごとの揺れ（0.001）より十分大きい（1.2節）
2. **追従（主）を満たす条件（exp015・exp016・exp018）は、あわせて正解0の窓の雑音下まとめも満たさない**（0.5074〜0.6465）。exp017 はこれを満たすが、追従（12.819）を満たさない
3. **2つの変更を組み合わせた exp018 でも、効果は足し合わされず、雑音下まとめ MAE は exp016・exp017 より悪かった**（2.2節）。指示書タスク2の範囲の変更（選び直しの回数、無音サンプルの割合）では、雑音下の基準に届かなかった

### 7.1 最も近い条件と、基準構成の扱いの提案

- **最も近い条件は exp016**（`configs/exp016.yaml`、選び直し1回）。追従 13.417（+0.417）・通常の話速域 0.4944・正解0の窓の clean 0.1876 を満たし、**雑音下まとめ MAE が 0.0290（0.7490 → 0.72）、正解0の窓の雑音下まとめが 0.0122（0.5122 → 0.5）足りない**。後者は揺れの中の差である（1.2節）
- 提案: 基準構成（比較の基準、既定のモデル）は exp005 のままとする。倍速再生への追従を優先する用途の「候補」としては exp016 を挙げるが、2節の基準を満たさないので、基準構成にも web/ の追加にもしない。人間が2節の雑音下の基準（0.72）の緩和、または雑音下の精度を落としてよいと判断した場合に限り、exp016 を倍速再生の用途のモデルとして扱う（9節の2・3）
- exp016 を exp018 より上に置く理由: 2節の基準の上で、雑音下まとめ MAE が 0.0193 良く（0.7490 と 0.7683）、x2 の天井はほぼ同じ（13.417 と 13.413）、正解0の窓の雑音下まとめの差（0.5122 と 0.5074）は揺れの中である

### 7.2 人間の承認の後に行う作業（人間が exp016 を web/ に加えると判断した場合のみ）

本書では web/ を変更しない。人間の承認があった場合の作業は次のとおり（web/README.md の手順）。

1. ONNX に書き出す: `uv run python -m spkrate.export.to_onnx --checkpoint runs/exp016/checkpoint_best.pt --out-dir runs/onnx_exp016`（CPU で行う。`runs/exp016/checkpoint_best.pt` は Mac の runs/ にある）
