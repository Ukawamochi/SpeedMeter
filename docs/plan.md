# 話速推定モデル開発計画

このファイルは統括Agentが読む実行計画である。上から順に実行する。

## このファイルの使い方

統括Agentは次のとおり動作する。

1. このファイルを最初に全文読む
2. docs/progress.md を読み、どこまで完了しているかを判定する
3. 未完了の最初の段階から実行する
4. 各段階の作業は、原則としてサブエージェントを起動して委譲する
5. サブエージェントの報告を受けたら、完了条件を照合する。満たしていれば docs/progress.md に追記し、次の段階へ進む
6. 「人間の作業」と記された段階に到達したら、必要な操作を提示して停止する

統括Agentは自分でコードを書かない。ファイルの読み取り、完了条件の照合、progress.md の更新、サブエージェントへの指示作成のみを行う。これはコンテキストを保つための分担であり、効率のためではない。

## サブエージェントの運用規則

- 1サブエージェントにつき1タスク。複数段階をまとめて渡さない
- サブエージェントに渡す情報は、CLAUDE.md、docs/spec.md、その段階の指示文、直前の段階の成果物パスのみ。過去の会話やログ全文を渡さない
- サブエージェントは作業完了時に、実施内容、生成したファイルのパス、得られた数値、未解決点を10行以内で報告する。詳細はリポジトリ内のファイルに書かせ、報告本文には含めない
- サブエージェントが仕様への疑問で停止した場合、統括Agentは自分で仕様を変更しない。docs/questions.md に疑問を転記し、人間の判断を求めて停止する
- 学習ログや大きな出力をサブエージェントの報告に含めない。ファイルに書き、統括Agentは指標のみ読む

## サブエージェントの種別

- 実装: コードとテストを書く
- 測定: スクリプトを実行し、結果をファイルに出力する
- 分析: テキストや数値を読んで分類・解釈する
- 判断: 結果を読み、次の条件や採否を決める

## 禁止事項

統括Agentおよび全サブエージェントに適用する。

- データセットのダウンロードを行わない。取得は人間が手動で行い、配置済みの前提で作業する
- docs/spec.md を人間の承認なく変更しない
- テストセット（configs/splits/test.json）を条件の選択に使わない。テストセットでの評価は第10段階のみ
- 音声を聴く判断を行わない。該当する場合は停止して人間に依頼する
- 学習を前景で実行しない。バックグラウンドで実行し、ログはファイルへ出力する

## 前提となる確定事項

### 作るもの

日本語の音声から話速（毎秒モーラ数）を推定する小型CNN。書き起こしは行わない。最終的にONNXへ書き出し、ブラウザ上で常時動作させる。

### 仕様（docs/spec.md の要点）

- 入力: 16kHzモノラル音声、固定長窓2.0秒
- 出力: 窓に含まれるモーラ数（非負の連続値）
- 表示値: 出力を窓長で割った毎秒モーラ数
- 推論間隔: 0.25秒
- モーラの規則: 拗音（ャュョァィゥェォヮ）は直前の文字と合わせて1、ヵ・ヶは単独で1、ン・ッ・ーは各1、フィラーも数える、無音は0
- 前処理: 読み変換の前にNFKC正規化。読み変換後にカタカナ以外が残る文は学習データから除外
- 特徴量: 対数メルスペクトログラム、n_fft=400、hop_length=160、n_mels=80、f_min=0、f_max=8000、power=2.0、log(mel + 1e-6)
- 正規化: 学習データ全体の平均と標準偏差を固定値として使用。発話ごとの正規化は行わない
- モデル: 周波数方向を圧縮する2次元畳み込み層、時間方向の膨張畳み込み層、フレームごとのsoftplus出力、時間方向の総和
- 損失: 二乗誤差とポアソン損失を比較
- 評価指標: 毎秒モーラ数の平均絶対誤差、話速帯別（4未満、4以上6未満、6以上8未満、8以上）の平均絶対誤差、相関係数、1推論あたり処理時間、モデルサイズ
- 分割: 話者単位
- 書き出し: ONNX、int8動的量子化

### データセットと役割

- Common Voice Scripted Speech 27.0 - Japanese（CC0-1.0）: 学習に使う唯一の発話データ。検証済み約30万クリップ、話者約7,800人、平均クリップ長4.467秒。再ホスト・再共有は禁止
- JSUT: テキストのみ使用。音声は使わない
- jsut-label（sarulab-speech/jsut-label）: BASIC5000に対する人手注釈の仮名。読み変換の正解として使用
- JVS: 評価にのみ使用。学習には使わない
- MUSAN: 雑音重畳の素材
- 残響: pyroomacoustics で合成

### 学習環境

- Python、PyTorch、デバイスは mps
- float64を使わない。torch.compileを使わない
- 特徴量は事前計算してファイルに保存する

# 第1段階　読み変換の品質測定

## 目的

pyopenjtalkでテキストから数えたモーラ数が、人手注釈の仮名から数えた値とどれだけ一致するかを測定し、不一致の原因を分類する。教師データに含まれる誤りの量を把握するため。

## 前提

src/spkrate/labels/mora.py に to_kana、count_mora_from_kana、count_mora、has_unconverted が実装済みでテストが通っていること。data/jsut と data/jsut-label が配置済みであること。

## 1-1　測定（測定サブエージェント）

scripts/eval_mora_labels.py を作成して実行する。

1. data/jsut/basic5000/transcript_utf8.txt からIDと原文を読む
2. data/jsut-label/text_kana から同じIDの人手注釈の仮名を読む
3. 人手注釈の仮名に count_mora_from_kana を適用した値を正解とする
4. 原文に count_mora を適用した値を推定値とする
5. 全文で比較する

results/mora_label_eval.md に記載する項目。

- 対象文数、完全一致率、差の絶対値の平均
- 差の分布（0、1、2、3、4以上の件数）
- 文あたり平均モーラ数
- 相対誤差（差の絶対値の合計を正解の合計で割った値）
- 前処理の内容（記号・空白の扱い、NFKC正規化の適用箇所）
- IDが対応せずスキップした件数

results/mora_mismatch.tsv に不一致の全文を差の降順で出力する。列は、文ID、原文、人手注釈の仮名、pyopenjtalkの読み、正解モーラ数、推定モーラ数、差。

完了条件: 上記2ファイルが生成され、前処理の内容が明記されている。

## 1-2　原因の分類（分析サブエージェント）

results/mora_mismatch.tsv の各行について、原文、pyopenjtalkの読み、人手注釈の仮名を読み比べ、次に分類する。

- 数字の読み違い
- 固有名詞の読み違い
- 難読語・複数の読みを持つ語の選択誤り
- 送り仮名や活用による読み違い
- 記号・空白の前処理の差（読みは同じで数え方だけ違う）
- 人手注釈が実際の発話に合わせて原文と異なる読みになっている
- その他

不一致が200件を超える場合は差の降順で200件を分類し、残りは差の値ごとの件数のみ集計する。

results/mora_mismatch_analysis.md に記載する項目。

- 分類ごとの件数
- 各分類の代表例を3件ずつ
- 「前処理の差」に分類された件数と、それを除いた場合の完全一致率および相対誤差

推奨や改善案は書かない。分類と数値のみ。

完了条件: results/mora_mismatch_analysis.md が生成されている。

## 1-3　採否の判断（判断サブエージェント）

results/mora_label_eval.md と results/mora_mismatch_analysis.md を読み、docs/experiments/001-mora-label-quality.md に次を書く。

- 相対誤差の値と、それが教師データに与える影響の評価
- 前処理の差を除いた実質的な誤り率
- このラベル生成処理をこのまま採用するか、除外規則を追加するか、別手段を検討するかの結論
- 除外規則を追加する場合、どの分類の事例を除外するかの具体的な条件

判断の基準: 前処理の差を除いた相対誤差が3パーセント以内であれば採用する。3から10パーセントであれば、誤りの多い分類に該当する文を除外したうえで採用する。10パーセントを超える場合は採用せず、停止して人間に報告する。この閾値は暫定であり、根拠となる測定値はない。判断サブエージェントは、この閾値で妥当かどうかの所見も記載する。

完了条件: docs/experiments/001-mora-label-quality.md に結論が書かれている。

## 1-4　除外規則の実装（実装サブエージェント）

1-3で除外規則を追加すると結論した場合のみ実行する。

src/spkrate/labels/filter.py に should_exclude(text: str) -> tuple[bool, str] を実装する。除外する場合はTrueと理由の文字列を返す。除外条件は1-3の結論に従う。単体テストを付ける。

完了条件: pytestが通る。

# 第3段階　ベースラインの実装と測定

単体テストを付ける。

調整後の値で検証セットを評価し、metrics.csv に追記する。

完了条件: metrics.csv に信号処理ベースラインの行がある。

## 3-3　書き起こしベースライン（実装サブエージェント）

# 第4段階　特徴量とデータ拡張

## 4-1　特徴量の事前計算（実装サブエージェント）

src/spkrate/features/melspec.py に、仕様のパラメータで対数メルスペクトログラムを計算する処理を実装する。

scripts/precompute_features.py で、学習・検証の全クリップの特徴量を計算し、data/processed/features/ にmemmapまたはnpyで保存する。保存形式と読み出し方法を docs/decisions/004-feature-storage.md に記録する。

学習データ全体から平均と標準偏差を計算し、configs/normalization.yaml に保存する。

完了条件: 特徴量が保存され、正規化の値がconfigsにある。

## 4-2　データ拡張（実装サブエージェント）

src/spkrate/data/augment.py に実装する。

- 時間伸縮: 0.7倍から1.5倍、音程を保持する。モーラ数は不変
- 雑音重畳: MUSANの雑音、SNR0dBから20dB
- 残響: pyroomacousticsで部屋のインパルス応答を生成して畳み込む
- 音量変化
- 帯域制限

時間方向のマスクは正解と矛盾するため実装しない。周波数方向のマスクのみ可とする。

各拡張について、適用前後でモーラ数のラベルが変わらないことを確認する単体テストを書く。

完了条件: pytestが通る。

## 4-3　窓の切り出し方式の決定（判断サブエージェント）

学習時の入力単位を決める。選択肢は2つ。

- 方式A: クリップ全体を入力とし、クリップ全体のモーラ数を正解とする。実装が単純。ただし推論時の2秒窓と条件が異なる
- 方式B: 強制アライメントで各モーラの時刻を求め、クリップの任意の2秒区間を切り出して、その区間の正確なモーラ数を正解とする。学習と推論の条件が揃い、データ量も増える。アライメントの導入と誤りの検出が必要

results/common_voice_overview.md のクリップ長の分布を読み、docs/decisions/005-window-strategy.md に結論と理由を書く。

判断の材料: 平均クリップ長が4.467秒であり、2秒窓の2倍強である。クリップ全体で学習した場合、推論時の窓長との差がどの程度の影響を持つかは測定してみないと分からない。したがって、まず方式Aで第5段階を完了させ、ベースラインと比較できる状態を作ってから、方式Bを追加実験として評価するのが妥当である。この順序を覆す理由が見つかった場合のみ、方式Bから始める。

完了条件: docs/decisions/005-window-strategy.md に結論がある。

## 5-4　初回結果の判定（判断サブエージェント）

# 第6段階　誤り分析

## 6-1　誤り事例の抽出（測定サブエージェント）

完了条件: 音声ファイルと一覧が出力されている。

## 6-2　テキスト面の分析（分析サブエージェント）

index.tsv を読み、音声を聴かずに判断できる範囲で誤差の原因を分類する。

- ラベル自体が誤っている（読み変換の誤り）
- 極端に短いまたは長いクリップ
- 毎秒モーラ数が分布の端にある
- 原文に特殊な表記が含まれる
- テキストからは原因が判断できない

results/error_analysis_text.md に分類ごとの件数と代表例を書く。

完了条件: 上記ファイルが生成されている。

## 6-3　聴取（人間の作業）

- 雑音が大きい
- 残響が強い

- 笑い声・咳などの非言語音
