# 疑問・課題記録

## 記録

### 2026-09-20 第2段階 モーラ数カウント実装時の疑問

1. 小書き文字ヵ・ヶ・ヮの扱いが仕様に明記されていない。仕様（docs/spec.md）およびタスク指示で挙げられている小書き文字はャュョァィゥェォのみで、ヵ・ヶ（「〜ヶ月」等に出現）・ヮ（クヮ等）については「直前の文字と合わせて1モーラ」に含めるべきか、単独で1モーラとすべきかの規定がない。現在の実装ではこれら3文字を結合対象に含めず、単独で1モーラとしてカウントしている。該当表記が実データに現れた場合の扱いを確認したい。
2. pyopenjtalk.g2p(kana=True)は全角ラテン文字（例:「Ｃ言語」の「Ｃ」）や丸囲み数字（①②③）を読みに変換せず、原文字のまま返す。read_kanaは「記号や空白を除去する」という仕様に従いカタカナ以外の文字を除去するため、これらの文字は発話上のモーラを持つはずでも実装上は無音（0モーラ）として扱われる。実データにこの種の表記が含まれる場合、モーラ数が過小に算出される。
3. 半角カタカナを含む入力に対し、pyopenjtalk.g2p(kana=True)が私有領域（Private Use Area）の文字を含む不正な文字列を返す事例を確認した（例:「ｶﾅ」→ 制御的な文字が混入し読みが破綻する）。半角カタカナがコーパス側に含まれる場合はNFKC正規化等の前処理が必要になる可能性があるが、仕様に規定がないため対応を保留した。
4. 小書き文字（ャュョァィゥェォ）が文字列の先頭に単独で出現し直前の文字が存在しない場合のモーラ数の扱いが規定されていない。現在の実装ではこの場合、当該小書き文字は単に無視され0モーラとして扱われる。pyopenjtalkの通常出力ではこの状態は生じにくいが、想定外の入力が来た場合の扱いを確認したい。

いずれも上記の理由によりテストケースには含めず、本記録のみとした。
