# 拡張設定の学習開始前検査

対象: `src/spkrate/data/augment.py`（`validate_augment_config`）と `src/spkrate/train/train.py`（`check_augment_setup`）。
`run_training` の冒頭、データ読み込みとモデル構築より前で `check_augment_setup` を呼ぶ。条件に当たると `AugmentSetupError`（`ValueError` の派生）を投げ、理由を log.txt に `拡張の設定の誤りで停止する: …` として書く。
参考: results/augmentation_check.md 3.2節。テスト: `tests/test_augment_validation.py`。
2026-09-24 の回答（docs/questions.md「2026-09-24 回答（拡張設定の学習開始前検査で保留した4件）」）を反映した（3節）。

拡張ごとに個別の有効フラグ `time_stretch_enabled`・`reverb_enabled`・`noise_enabled`・`band_limit_enabled`・`volume_enabled`・`freq_mask_enabled`（`augment.params` に書く。既定はすべて true）がある。false の拡張は適用せず、抽選もしない。

## 1. 学習開始前に停止させる条件（`augment.enabled: true` のときだけ検査する）

条件1〜3は雑音重畳が個別に有効（`noise_enabled: true`）なときだけ、条件5〜20・22は、その項目が属する拡張が個別に有効なときだけ検査する。個別に無効な拡張の確率や範囲は使われないので検査しない。

| # | 条件 | 停止しない場合に起きること |
| ---: | --- | --- |
| 1 | `augment.musan_root` が未設定 | 雑音源が `None` になり、雑音重畳が一度も行われない（augment.py `augment_waveform` の雑音の分岐）。警告も出ない |
| 2 | `musan_root` がディレクトリとして存在しない | データセット構築の段階で FileNotFoundError になる。これはモデル構築の後 |
| 3 | `musan_root/noise` が無い、または wav が0件 | 2と同じ |
| 4 | `data.source` が `features`（拡張ありなのに事前計算特徴量を使う設定） | 拡張は波形に掛かるので実行されない。これまでは `build_datasets` で止まっていたが、モデル構築の後だった |
| 5 | 個別に有効な拡張の確率 `*_prob` が0（時間伸縮・残響・雑音重畳・帯域制限・音量変化・周波数マスク） | その拡張が一度も実行されない。外すなら `<名前>_enabled: false` と書く（メッセージでも案内する） |
| 6 | 確率が0未満か1を超える、または有限でない | 設定の誤り |
| 7 | 範囲の下限が上限を超える、または有限でない値がある（範囲の項目すべて） | 最初のサンプルで `_uniform` が ValueError を投げる（学習の途中） |
| 8 | `time_stretch_range` が (1.0, 1.0) | 時間伸縮は常に無変化 |
| 9 | `time_stretch_range` の下限が0以下 | 伸縮率が0以下になり、学習の途中で ValueError |
| 10 | `librosa` を読み込めない | 最初の時間伸縮で ImportError（学習の途中） |
| 11 | `pyroomacoustics` または `scipy` を読み込めない | 最初の残響・帯域制限で ImportError（学習の途中） |
| 12 | `rt60_range` の下限が0以下 | 残響時間が0以下になる |
| 13 | 部屋の寸法の範囲の下限が1.0 m未満 | 音源とマイクの位置（壁から0.5 m）を引く範囲が空になり、学習の途中で ValueError |
| 14 | `reverb_max_order` が1未満 | 反射が計算されず、直接音だけの応答になる（残響は付かない） |
| 15 | 最小の部屋と最長の RT60 の組でも `pra.inverse_sabine` が失敗する | `generate_rir` が毎回無響の応答 `[1.0]` を返し、残響は一度も付かない |
| 16 | `low_hz_range` の上限が0以下で、かつ `high_hz_range` の下限がナイキスト周波数（8000 Hz）以上 | 帯域制限は常に無変化 |
| 17 | 低域遮断と高域遮断の範囲が重なる | 通過帯域が空になる組が引かれうる。引かれると学習の途中で ValueError |
| 18 | `band_limit_order` が1未満 | フィルタ設計の誤り |
| 19 | `gain_db_range` が (0.0, 0.0) | 音量変化は常に無変化 |
| 20 | `freq_mask_num` または `freq_mask_max_width` が0以下 | 周波数マスクは常に無変化 |
| 21 | `sample_rate` が16000でない | docs/spec.md の入力は16kHz。残響と帯域制限の周波数計算がずれる |
| 22 | `time_stretch_range` が0.7〜1.5倍、`snr_db_range` が0〜20 dB（どちらも両端を含む）の外に出る | docs/spec.md「データ拡張」の範囲を外れる。範囲を変えるなら先に docs/spec.md を更新する（回答3）。spec.md に範囲の無い項目（RT60、部屋、利得、遮断周波数など）には制約を設けない。内側に狭めるのは許す |
| 23 | 個別の有効フラグ `*_enabled` が true・false 以外（文字列 `"false"` など） | 文字列は真と解釈され、外したつもりの拡張が掛かる |

既定値（`AugmentConfig()`）と `musan_root: data/musan` の組み合わせはどの条件にも当たらない。実データでも確認し、雑音源は data/musan/noise の930ファイルだった。

## 2. 停止させないもの（サンプル単位で起きる正当なスキップ・変化）

| 箇所 | 事実 | 停止させない理由 |
| --- | --- | --- |
| `add_noise` | 信号の電力が1e-12以下（無音）なら雑音を足さない | 無音区間ではSN比が定義できない。サンプル単位の正当なスキップ |
| `add_noise` | 切り出した雑音の電力が1e-12以下なら足さない | 雑音ファイル側の無音区間。サンプル単位 |
| `change_volume` | `peak × gain > 0.99` のとき利得を `0.99 / peak` に抑える | クリップによる歪みを避けるため。正の利得が指定値より小さくなることがある |
| `generate_rir` | 引いた部屋の寸法と RT60 の組が実現できないと無響の応答 `[1.0]` を返す | 一部の組でだけ起きる。既定の範囲では残響を選んだ回の約3.9%（20,000回の抽選で測定、シード0）。最大の部屋（10×10×4 m）に RT60=0.1 秒を組み合わせると実現できない。どの組でも実現できない場合は条件15で止める。既定の範囲は変えず（回答4）、実際の適用率を学習開始時のログに記録する（4節） |
| `generate_rir` | 応答のピークが1e-12以下なら `[1.0]` | 実際にはほぼ起きない |
| `band_limit` | 波形が24標本以下なら零位相フィルタを掛けない | 1.5ミリ秒以下の波形。実際のクリップでは起きない |
| `band_limit` | 引いた高域遮断がナイキスト周波数以上なら低域通過を省く。引いた低域遮断が0なら高域通過を省く | 範囲の一端でだけ起きる。既定の範囲では、低域遮断がちょうど0になる確率は0、高域遮断の上限は7800 Hz |
| `time_stretch` | 引いた伸縮率がちょうど1.0なら無変化 | 起きる確率は0 |
| `frequency_mask` | マスクの幅に0が引かれると、そのマスクは掛からない | 1本あたり1/13（既定の最大幅は12） |
| `build_datasets` | 検証セットには拡張を掛けない | 設計どおり（006の1節）。検証は常に features 経路 |
| `_build_noise_source` | 拡張ありで `musan_root` が無いか、雑音重畳が個別に無効なら `None` を返す | 雑音重畳が有効なら条件1が先に止める。無効なら雑音源は使わない |
| `check_augment_setup` | `augment.enabled: false` なのに `augment.params` や `augment.musan_root` が書かれている | 止めずに警告（logging.WARNING）を出し、log.txt にも残す（回答1）。書かれた項目は使われない |
| `validate_augment_config` | `augment.enabled: true` で個別の拡張が `*_enabled: false`（全種 false も含む） | エラーにしない。その拡張は適用しない（回答2）。log.txt には `拡張: <名前> 無効（<名前>_enabled=false）` と書く |

`AugmentResult.applied` には、`add_noise` が無音で雑音を足さなかった回と、`generate_rir` が無響の応答を返した回も、それぞれ `noise`・`reverb` として記録される。実際に波形を変えた拡張だけを `AugmentResult.effective` に記録する（伸縮率ちょうど1.0、無響の応答、無音で雑音なし、フィルタ無し、利得0 dB を除く）。

## 3. 保留していた4件の解消（docs/questions.md 2026-09-24 回答）

## 4. log.txt の先頭の形式

`run_training` は学習ループより前に、次の順で書く。1行目にコミットと設定ファイル、続いて拡張の一覧、設計上の確率と実際の適用率。拡張が無効なら一覧の代わりに `拡張=なし` の1行を書く（`params` や `musan_root` が書かれていれば、その前に WARNING の行が出る）。
その後に、実験ID・デバイスの行、モデル、データの行が続く。

実際の適用率は、学習開始前に固定シード0で2000回、`AugmentConfig` に従って抽選とパラメータ生成だけを行って実測する（波形は処理しない。所要は1秒未満）。「実際には適用されなかった」と数えるのは、残響で無響になる組、伸縮率ちょうど1.0、利得ちょうど0 dB、低域も高域も削らない帯域制限、幅0だけの周波数マスクで、いずれもパラメータだけで決まる。無音への雑音・音量の上限クリップなど波形に依存するスキップは含まない。個別に無効な拡張の設計上の確率は0と書く。

```
… INFO コミット=7d743c1… 設定=configs/expNNN.yaml
… INFO 拡張=あり 適用順=時間伸縮→残響→雑音重畳→帯域制限→音量変化（波形）→周波数マスク（特徴量）
… INFO 拡張: 時間伸縮 確率=0.5 伸縮率=0.7〜1.5倍
… INFO 拡張: 残響 確率=0.3 RT60=0.1〜0.7秒 部屋=3〜10×3〜10×2.3〜4m 最大反射次数=12
… INFO 拡張: 雑音重畳 確率=0.5 SNR=0〜20dB 雑音源=data/musan/noise（930ファイル）
… INFO 拡張: 帯域制限 確率=0.25 低域遮断=0〜300Hz 高域遮断=3400〜7800Hz 次数=4
… INFO 拡張: 音量変化 確率=0.5 利得=-12〜6dB
… INFO 拡張: 周波数マスク 確率=0.5 本数=2 最大幅=12メル 埋める値=0
… INFO 拡張の適用率（学習開始前に固定シード0で2000回抽選・パラメータ生成）: 設計=設定上の確率 実際=実際に掛かった割合（…）
… INFO 適用率: 時間伸縮 設計=0.500 実際=0.488（抽選に当たった976回のうち976回が実際に掛かった／2000回）
… INFO 適用率: 残響 設計=0.300 実際=0.280（抽選に当たった589回のうち560回が実際に掛かった／2000回）
… INFO 適用率: 雑音重畳 設計=0.500 実際=0.466（抽選に当たった931回のうち931回が実際に掛かった／2000回）
… INFO 適用率: 帯域制限 設計=0.250 実際=0.243（抽選に当たった486回のうち486回が実際に掛かった／2000回）
… INFO 適用率: 音量変化 設計=0.500 実際=0.509（抽選に当たった1018回のうち1018回が実際に掛かった／2000回）
… INFO 適用率: 周波数マスク 設計=0.500 実際=0.515（抽選に当たった1035回のうち1031回が実際に掛かった／2000回）
```

上の適用率は既定値（`AugmentConfig()`）での実測値である。「設計」と「実際」の差には、確率の抽選の揺らぎ（2000回で標準偏差約0.011）と、抽選に当たっても掛からなかった回の両方が入る。後者は括弧内の2つの回数の差で読む。残響は抽選に当たった589回のうち29回（4.9%）が無響になった（同じ関数で20,000回にすると5,967回のうち261回、4.4%。以前の測定の約3.9%とは乱数の引き方が異なる）。周波数マスクは2本とも幅0になった4回（期待値は1/169）が適用なしになった。

学習中は、エポックごとの学習を終えた時点で、実際に掛かった拡張の回数を1行書く（`AugmentResult.effective` と、周波数マスクが実際に掛かった回を数える。metrics.jsonl の列は変えない）。

```
… INFO エポック1 拡張の実適用回数（学習236143件中）: 時間伸縮=…(0.49…) 残響=…(0.28…) 雑音重畳=… 帯域制限=… 音量変化=… 周波数マスク=…
```
