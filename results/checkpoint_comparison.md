## 3. 実際に保存されているチェックポイント

`runs/exp003/` に実際にディスク上に存在するチェックポイントファイル（2026-09-25 時点、`ls -la` で確認）:

- `checkpoint_best.pt`（2,007,661 バイト、更新日時 2026-09-25 00:49 → エポック25の記録時刻
  `2026-09-25T00:49:21+09:00` と一致）
- `checkpoint_last.pt`（6,014,075 バイト、更新日時 2026-09-25 02:00 → エポック29の記録時刻
  `2026-09-25T02:00:06+09:00` と一致）

上記2ファイルのみで、`checkpoints/epoch_*.pt` のようなエポックごとの個別ファイルは存在しない。

保存方式（`src/spkrate/train/train.py` の `run_training` 内、`save_checkpoint` の呼び出し箇所。
このタスク開始時点では次の2箇所のみだった）:

- `checkpoint_last.pt`: 毎エポック終了時に**同じパスへ上書き**保存（`optimizer_state` を含む。
  再開用）。
- `checkpoint_best.pt`: そのエポックの `train.best_metric`（既定 `mae_moras_per_sec`）が
  それまでの最良を更新したときのみ**同じパスへ上書き**保存（`optimizer_state` を含まない）。

この「最良のみ上書き保存」方式のため、過去に一度 `is_best=True` だったが後のエポックで
上書きされたチェックポイント（例: エポック21・23の重み。metrics.jsonl 上は
`is_best=True` の記録が残るが、実際の重みファイルは現存しない）は、現時点のディスク上には
存在しない。現存する `checkpoint_best.pt` はエポック25（現時点での最新の最良）の重みのみである。
エポックごとの個別保存は、このタスク開始時点のコードには実装されていなかった。

## 4. エポックごとのチェックポイント保存の実装（コード変更のみ、再学習なし）

対象コミット時点で `src/spkrate/train/train.py` の `save_checkpoint` 呼び出しが
`checkpoint_last.pt` と `checkpoint_best.pt` の2箇所のみであることを確認した上で、以下を実装した。

- `TrainSettings`（`src/spkrate/train/train.py`）に `save_every_epoch: bool = True` を追加。
- `run_training` のエポックループで、`checkpoint_last.pt` の保存直後・`is_best` 判定より前に、
  `config.train.save_every_epoch` が真のとき
  `run_dir / "checkpoints" / f"epoch_{epoch:03d}.pt"` へ個別にチェックポイントを保存する処理を追加。
  保存内容は `checkpoint_best.pt` と同じ呼び出し形（`model`, `epoch`, `metrics=row`, `config`,
  `normalizer`）で、`optimizer_state` は含めない（`save_checkpoint` の既定どおり、
  `model_state` / `model_config` / `epoch` / `metrics` / `train_config` / 正規化の平均・標準偏差を含む）。
  `checkpoint_last.pt` / `checkpoint_best.pt` の既存の保存処理・書き込み先は変更していない。
- 既存の設定ファイル（`configs/*.yaml`。`configs/exp003.yaml` を含む）は変更していない。
  `save_every_epoch` の既定値が `True` のため、これらの設定ファイルは明示的に指定しなくても
  エポックごとの個別保存が有効になる（既存実験の再現性・設定内容には影響しない。実行中の
  exp003プロセスはメモリ上に読み込み済みの設定を使っており、今回のコード変更・設定ファイル
  不変更のいずれも exp003 の実行中プロセスに影響しない）。
- モジュール docstring（`src/spkrate/train/train.py` 冒頭）に、出力ファイル一覧表への追記と
  「エポックごとの個別チェックポイント保存」節を追加した。
- テストを `tests/test_train.py` に追加（3件）。
  - `test_save_every_epoch_defaults_to_true`: 設定を書かない場合に `save_every_epoch` が
    `True` になること。
  - `test_save_every_epoch_writes_one_checkpoint_per_epoch`: 4エポックのスモーク学習で
    `checkpoints/epoch_001.pt`〜`epoch_004.pt` が作られ、`checkpoint_last.pt` /
    `checkpoint_best.pt` の保存も従来どおり行われ、各 `epoch_*.pt` の中身
    （`epoch`・`metrics`・`train_config`）がそのエポックの `metrics.jsonl` の記録と一致し、
    `optimizer_state` を含まないことを確認。
  - `test_save_every_epoch_false_skips_individual_checkpoints`: `save_every_epoch: false` の
    とき `checkpoints/` ディレクトリ自体が作られず、既存の2ファイルの保存には影響しないこと
    を確認。
  - `uv run pytest -q` で全件（552件）が通過することを確認した（対象コミットの変更前後で
    件数の差は追加した3件のみ）。

### ディスク容量（事実。推奨・意見ではない）
