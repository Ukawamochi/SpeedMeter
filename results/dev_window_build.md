# 窓単位の評価セット dev_window の構築（指示書 2026-09-25 タスク5-1）

- 設定: `configs/eval/dev_window.yaml`
- 実装: `src/spkrate/eval/dev_window.py`（生成・保存・波形の再生成）、入口 `scripts/build_dev_window.py`
- 単体テスト: `tests/test_dev_window.py`
- 出力: `data/processed/dev_window/`（Git管理外。`sources.jsonl`・`windows.npz`・`meta.json`、計15MB）
- 入力: `configs/splits/dev.json` の話者のクリップ（`data/processed/clips.jsonl`）と `data/processed/alignments/dev.jsonl`（29,518件、全件 ok）。`configs/splits/test.json` は使わない
- 前提: `results/alignment_check/record.md` は人間の一括判定で「大きくずれる・失敗」0件（指示書の停止条件に該当しない）

## 1. 生成方法

### 1.1 窓

- 長さ2.0秒（32,000標本）の窓を0.25秒（4,000標本）ずつずらす（docs/spec.md の入力単位と推論間隔）
- 窓の開始は 0, 0.25, 0.5, … 秒。**音声の中に窓全体が収まるものだけを取り、詰め物をしない。末尾の端数（0.25秒未満のずれ）は捨てる**。`src/spkrate/eval/window_diag.py` の `split_into_windows`（D1）と同じ規約（窓は波形の内側だけから取り、末尾の半端は捨て、窓長に満たない波形からは窓を取らない）に合わせた
- したがって **2.0秒未満のクリップは単一クリップの窓を持たない**（1,626件。連続発話の組には使う。3節の「未解決点」を参照）

### 1.2 正解（按分）

- 窓 [t, t + 2.0) の正解 = Σ（モーラ区間 [start, end] のうち窓内に入る長さ ÷ (end − start)）
- end <= start の区間は点とみなし、t <= start < t + 2.0 なら1、それ以外は0とする。dev の除外後のクリップには該当する区間が無かった（0件）
- 計算は float32（`window_mora`）

### 1.3 単一クリップ（kind=single）

除外後の各クリップをそのまま音源にして窓を切る。

### 1.4 連続発話（kind=concat）

- 同一話者（client_id）の除外後のクリップを連結する（`build_concat_groups`）
  1. 話者ごとに clip_id 順に並べ、`numpy.random.default_rng([seed, clip_key(client_id)])` の `permutation` で並べ替える（`clip_key` は dev_noisy と同じ SHA-256 の先頭8バイト。話者の並び順や他の話者に依存しない）
  2. 残りが3件以上のあいだ、件数 k を3〜5の整数一様乱数で引き（残りより多ければ残り全部）、先頭から k 件を1組にする。続けて k − 1 個の無音長を一様乱数 [0.3, 1.5) 秒から引き、0.01秒単位に丸める
  3. **各クリップは高々1回使う**。3件に満たない残り（1〜2件）と、除外後のクリップが3件未満の話者は連結に使わない
- 無音は全標本0（D3 と同じデジタル無音）。クリップ自身の前後の無音はそのまま残る
- 正解は各クリップのモーラ時刻を、連結音声内でのそのクリップの開始位置（先行クリップの長さと無音長の和）だけずらして同じ按分で数える
- 乱数の種: 20260927（設定の `seed`）。単一クリップの窓は種に依存しない

### 1.5 除外（results/alignment_dev.md 3.4節）

- アライメント失敗（ok=false）
- 先頭2モーラまたは末尾2モーラの開始時刻の差が1.0秒を**超える**（>）クリップ
- 単一クリップからも連続発話の組からも除く（組はこの除外の後に作る）

### 1.6 known_no_speech の印（除外しない）

`results/error_cases/to_listen.tsv` の37件（results/error_analysis_audio.md。人間の聴取で「発話が聞き取れない」がアライメントは ok）。これらを由来に持つ単一クリップの窓と、1件でも含む連結の組のすべての窓に `known_no_speech` を付ける。

### 1.7 雑音下の版

- 設定の `noisy` 節は `configs/eval/dev_noisy.yaml` と同じ値（SNR 5・10・15dB、固定残響、乱数の種 20260924、MUSAN noise は `configs/splits/musan_noise.json` の評価用 186ファイルのみ）。一致は単体テストで確認する
- 音源（単一クリップまたは連結音声）の**全体**に `spkrate.eval.noisy.degrade_waveform`（固定残響 → 雑音）を掛けてから窓を切る。SNR は音源全体の実効値に対する比
- 雑音の乱数生成器の鍵: 単一クリップは clip_id（dev_noisy のそのクリップと同じ雑音ファイル・切り出し位置になる）、連続発話は `"concat:" + clip_id を "+" でつないだ文字列`

### 1.8 保存と再生成

- 窓の音声は保存しない。`sources.jsonl`（音源ごと: id、single/concat、話者、clip_id の列、各クリップの標本数・連結音声内の開始標本、無音の標本数、known_no_speech）と `windows.npz`（窓ごと: 音源の番号、開始標本、正解モーラ数、single/concat、known_no_speech）、`meta.json`（件数・除外した clip_id・生成時のコミット）
- 波形は `DevWindowAudio.window_at(window_set, i, snr_db=None|5|10|15)` で再生成する。クリップの長さがアライメント時（`duration_sec` × 16000）と違えば停止する
- 代表4窓（単一2・連続2）で clean と SNR 5dB の波形を2回ずつ再生成し、長さ32,000標本・ビット一致を確認した（`meta.json` の `waveform_checks`）

## 3. 既知の限界と未解決点

- **モーラ区間はピーク状**（約9割が1フレーム≈20ms。docs/decisions/008-forced-alignment.md 4節）なので、按分は実質的にモーラの時刻（点）の計数に近い。窓の端でモーラが切られる割合は区間長の分だけで、整数でない正解は窓の2〜3割にとどまり、端数は1モーラ分の一部だけである。按分が「窓内の発音時間の割合」を表すわけではない
- 008 4節は窓の数え方として「区間の中点」を推奨していたが、本セットは指示書の按分に従った。区間が約20msなので中点での計数との差は窓の端の1モーラ分以内
- アライメントの時刻の精度は聴取で30件を一括で確認しただけ。端のモーラの位置は±1フレーム程度揺れる（results/alignment_dev.md 3.3節）。窓の正解はこの誤差を含む
- 端の孤立は2モーラの間隔だけで判定した。3モーラ目以降が孤立する例や、1秒以下の孤立は残る
- known_no_speech の37件は発話が聞き取れないのにアライメントは全モーラを置いている。これらの窓の正解はアライメントが置いた位置での計数であり、実際の音声とは合わない可能性が高い（除外はせず印だけ付けた）
- 連続発話の無音はデジタル無音（全標本0）で、雑音下の版では雑音が無音部分にも乗る。正解0の窓はクリップ自身の前後の無音と挿入した無音からなる
- 雑音下の版の SNR は音源全体の実効値に対する比なので、連結音声（無音を多く含む）と単一クリップで、発話区間あたりの実効の SNR が異なる
- **未解決点（確認を要する）: 2.0秒未満のクリップ（1,626件、dev の5.5%）は単一クリップの窓を持たない。** 仕様（入力単位は固定長窓2.0秒）と `window_diag.split_into_windows`（窓長に満たない波形からは窓を取らない、詰め物をしない）に合わせてこう扱ったが、詰め物（前後に無音を足して2.0秒にする）をして評価に含める案もありうる。これらのクリップは連続発話の組には入っている（組に入らなかった分を除く）
