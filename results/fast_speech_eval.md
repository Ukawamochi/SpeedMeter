# 高速度域の評価（指示書 2026-09-28-fast-speech タスク1）

- 目的: 速い発話で出力が頭打ちになる問題について、正解の話速の区間別に出力が正解に追従しているかを測る。評価1は dev_window（clean・主指標）の区間別、評価2は速めた音声 dev_fast（WSOLA で1.5倍速・2倍速。作り方は results/dev_fast_build.md）の区間別
- 区間は窓の正解の毎秒モーラ数で、6未満（lt6）、1刻みの 6以上7未満（6to7）〜13以上14未満（13to14）、14以上（ge14）。偏り = 出力 − 正解 の平均。値はすべて主指標（dev_window と同じ除外の後）
- **本書は測定値と判定の基準だけを記録する。採否の判断はしない**（タスク3が docs/experiments/013-fast-speech.md で行う）
- configs/splits/test.json は使っていない。音声は聴いていない

## 1. 判定の基準（exp014・exp015 の結果が出る前、exp010 の値を見る前に固定した）

手順: exp005・exp007 の評価1・評価2を先に測り（3節）、その区間別の差を「区間別の偶然の揺れの目安」とした。基準はその値だけから決め、exp010 の集計はこの節をコミット（326471d）した後に行った（exp010 の評価2の推論は3モデルまとめて先に遠隔機で行ったが、その出力はコミットまで開いていない）。exp014・exp015 はまだ学習していない。

exp005（mps で学習、種 20260921）と exp007（cuda で学習、種 20260929）の、同じ区間の出力の平均の差 |exp005 − exp007|（区間の正解の平均は2つで同じなので、偏りの差と等しい）:

| 8to9 | 0.050 | 0.015 | 0.014 |

### 1.3 高速度域の基準（主な判定）

判定に使う6つのセル: {評価1, 評価2 x1.5, 評価2 x2} × {12to13, 13to14}。

| # | 名前 | 判定の仕方 | 基準の値（exp005・exp007 の範囲から） |
| --- | --- | --- | --- |
| F1 | 偏りの改善 | セルごとに、条件の \|偏り\| が基準の範囲の \|偏り\| の小さい方より s_bin 以上小さいとき「改善」、大きい方より s_bin 以上大きいとき「悪化」、それ以外は「差なし」。**6セルすべてが改善のとき F1 を満たす** | \|偏り\| の上限（改善とみなす値）: 評価1 12to13 ≤ 1.424、13to14 ≤ 2.199、x1.5 12to13 ≤ 1.148、13to14 ≤ 1.608、x2 12to13 ≤ 2.690、13to14 ≤ 2.941 |
| F2 | 追従（人間の目標「正解13〜14で出力が正解に追従する」） | セルごとに \|偏り\| ≤ T を「追従」とする。**T = 0.5 mora/s**。評価1の2セルがともに追従のとき F2 を満たす。評価2のセルの追従は、F2' と合わせて記録する | 基準では評価1 12to13 1.534〜1.640、13to14 2.309〜2.368（未達） |
| F2' | 評価2の相対の追従 | 評価2では、速めた音声そのものによる過小評価が通常の話速の区間にもある（基準の 6to7〜8to9 の偏り: x1.5 で −0.48〜−0.57、x2 で −1.24〜−1.85。3.2・3.3節）。そこで、同じモデル・同じ条件の 6to7・7to8・8to9 の偏りの平均を b_ref とし、相対の偏り = 偏り − b_ref とする。\|相対の偏り\| ≤ T のとき「相対の追従」とする。評価2の4セルは、絶対（F2 と同じ T）と相対の両方を記録する | 基準の相対の偏り: x1.5 12to13 −0.75〜−0.80、13to14 −1.21〜−1.25、x2 12to13 −1.27〜−1.30、13to14 −1.52〜−1.56（b_ref は x1.5 で −0.51〜−0.52、x2 で −1.53〜−1.55） |
| F3 | 単調な増加 | 評価ごとに、6to7 → 7to8 → … → 13to14 の隣り合う区間で、出力の平均の増分がすべて s_bin（0.11）以上のとき「単調」とする。**3つの評価すべてで単調のとき F3 を満たす**。13to14 → ge14 の増分は記録するが判定に使わない（ge14 は正解の幅が広く、評価1では窓数が少ない） | 基準は3つの評価とも単調（評価1の最小の増分は 12to13 → 13to14 の 0.22〜0.27）。13to14 → ge14 は評価1で −0.88（減少）、x1.5 で +0.53〜+0.58、x2 で +1.75〜+1.76 |
| F4 | 天井（記録） | 天井 = 評価ごとの区間の出力の平均の最大値（lt6〜ge14）。基準の範囲の上端より何 mora/s 上がったかを記録する。人間の目標の「2〜3 mora/s 上げる」に対応させ、**評価1の天井が 基準の上端 + 2.0 以上**になったかを記録する | 基準の天井: 評価1 10.916〜10.974（13to14）→ 目標の目安 ≥ 12.97。x1.5 12.116〜12.117（ge14）、x2 11.941〜12.010（ge14） |

- T = 0.5 の理由: 基準（exp005・exp007）の評価1で、\|偏り\| は 9to10 まで 0.26 以下、10to11 で 0.49〜0.58 に増える。指示書の背景の「10以上で過小評価が急に大きくなる」の境目の大きさであり、clean・主指標の全体の MAE（0.48）とも同程度である。この大きさ以下なら、13〜14 の窓が通常の話速域の上端（10前後）と同程度に扱えていると読む
- 境目の扱い（011-search-plan.md 2.1節と同じ）: F1 の改善・悪化が s_bin の1〜1.5倍の差で決まるセルは「境目」と注記する

## 2. 実行の記録

- 評価1: 既存の dev_window の予測（exp005 は `runs/exp005/window_eval`（mac・mps）、exp007 は `runs/exp007_eval/window_eval`、exp010 は `runs/exp010_eval/window_eval`（ともに ubuntu-desktop・cuda））を Mac で集計した。推論はしていない
- 評価2: dev_fast（`data/processed/dev_fast/`）を `scripts/sync_to_remote.sh --data` で ubuntu-desktop に送り（19:13〜19:15、data の件数・バイト数一致、遠隔機の HEAD bd86044、git status は clean）、3モデルの `scripts/eval_fast_speech.py predict --device cuda` を tmux で順に実行した（19:17:57〜19:20:07、1モデル約40秒、CPU フォールバック0件、エラーなし）。checkpoint_best.pt は遠隔機に既にあり、md5 が Mac と一致した（exp005 375a0561…、exp007 6bdcd0f6…、exp010 b07f313c…）。予測は `scripts/fetch_from_remote.sh` で `runs/fast_speech_013_pred/` に戻し、`runs/<モデル>/fast_speech/`（exp007・exp010 は `runs/<モデル>_eval/fast_speech/`）に写して Mac で集計した（`fast_speech_summary.json`・`fast_speech_tables.md`）。起動スクリプトと補助の集計は `runs/fast_speech_013/`（Git 管理外）
- **dev_fast の遠隔機での確認**: `build_dev_fast.py --verify 20` は遠隔機で `VERIFY_MISMATCH` になった（窓の定義は一致、波形は 0/20 がビット一致せず、最大差 x1.5 0.46・x2 1.00）。原因を調べると、作り直しの入力である元の波形（`DevWindowAudio.source_waveform`）が Mac と遠隔機で float32 の丸めの大きさだけ違い（先頭の音源で最大差 1.8e-7、同じ numpy 2.5.3・scipy 1.18.1・audiotsm 0.1.2・librosa 1.0.0・libsndfile 1.2.2）、WSOLA のずれの探索（相互相関の最大の位置）がそれで別の位置を選ぶためだった。**評価2の推論は遠隔機で作り直した波形ではなく、Mac で作って送ったファイルを読む**。送ったファイル（selection.json と各条件の audio.npy・windows.npz・sources.jsonl・meta.json）の md5 が Mac と遠隔機ですべて一致することを確かめたので、推論の入力は Mac の dev_fast と同一である。dev_fast を遠隔機で作り直すと Mac の dev_fast とは一致しない（results/dev_fast_build.md 4節の手順は、送ったファイルの md5 の一致で確かめる形に読み替える必要がある）
- metrics.csv: `013-fast-speech-exp005`・`-exp007`・`-exp010` を各29行（評価1 9行、評価2 20行）。host・device は予測を作った計算機（exp005 の評価1だけ mac・mps、他は ubuntu-desktop・cuda）
- ubuntu-desktop は 19:20:07 に空いた（tmux のセッションなし）
